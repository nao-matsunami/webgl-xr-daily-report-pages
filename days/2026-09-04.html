three.js の WebGPURenderer autoSubmit / scheduled submits、PassNode pixel ratio修正、packed 4x8 integer dot product、PlayCanvas の次フレーム冒頭での async texture read copy、WireRenderer、SOG LOD bundle、Babylon.js の object ID geometry textures、ShadowOnlyMaterial IBL shadows、bounding box寸法表示を調査した。前回の velocity/datamosh/readback 遅延から、今日は「いつGPUへsubmitするか」「いつreadbackをcopyするか」「どのobjectがどのpixelを占めるか」を見える時間軸に置き、2本のWebGLサンプルを実装した。

Today covers three.js WebGPURenderer autoSubmit / scheduled submits, PassNode pixel-ratio fixes, packed 4x8 integer dot product support, PlayCanvas next-frame async texture-read copy, WireRenderer, a single streamed SOG LOD bundle, and Babylon.js object ID geometry textures, ShadowOnlyMaterial IBL shadows, and bounding-box dimensions. Building on yesterday's velocity/datamosh/readback delay, the focus shifts to making GPU submit timing, readback copy timing, and per-pixel object ownership visible. Two runnable WebGL samples were implemented.

制作に使えそうな技術メモProduction notes

WebGPU側で submit をまとめる場合、見た目の改善だけでなく、UI入力からGPU反映までのlatencyを測る必要がある。`performance.mark()` で input、render start、compute end、submit、readback copy、present 風の時刻を残すと、サンプルのshader uniformへ流せる。PlayCanvas #9293 の考え方は WebGL でも使える。readPixels / getBufferSubData を発行する場所をフレーム末尾固定にせず、次フレーム冒頭や負荷の低いpassへ逃がす設計にする。object ID texture はRGBA8 24-bitなら広いID空間、RED8なら軽い選択maskとして扱える。SOG LOD error metadata と合わせると、選択されたobjectだけ高LOD、周辺はwire/debug outlineという演出が組める。

If WebGPU submits are batched, measure not only visual improvement but input-to-GPU latency. Mark input, render start, compute end, submit, readback copy, and present-like timing with `performance.mark()` and feed those values into shader uniforms. The PlayCanvas #9293 idea applies to WebGL too: avoid always doing readPixels/getBufferSubData at frame end; move copies to the next frame start or a lighter pass. Object-ID textures can use RGBA8 for a 24-bit ID space or RED8 for a cheap selection mask. Combined with SOG LOD error metadata, selected objects can get high LOD while surroundings become wire/debug outlines.

サンプルデータの可能性と組み合わせ考察Possibilities for the sample data and combinations

今日の2本は、入力値と描画状態をデータ化すると接続しやすい。1本目は pointer queue pressure、submit pulse、readback age、pixel ratio drift をログ化できる。2本目は selected object id、LOD error、wire density、bounds pulseを持てる。MediaPipeの手速度をsubmit pressureへ、Web Audioの低域をreadback pulseへ、WebXRの床・壁・注視対象をobject IDへ、商品や展示物の実寸をbounds inspectorへ流すと、処理負荷と空間理解が同じ演出面に乗る。Webのページ遷移では、前ページのsubmit/readback履歴を次ページのobject outlineとして残すと、遷移がただのフェードではなく、GPU処理の余韻として見える。

The two samples connect well when inputs and render states are treated as data. The first can log pointer queue pressure, submit pulses, readback age, and pixel-ratio drift. The second can expose selected object IDs, LOD error, wire density, and bounds pulses. MediaPipe hand speed can drive submit pressure, Web Audio bass can drive readback pulses, WebXR floor/wall/gaze targets can feed object IDs, and real product dimensions can feed bounds inspection. For page transitions, carrying the previous page's submit/readback history into the next page's object outlines makes the transition read as residual GPU work rather than a simple fade.
