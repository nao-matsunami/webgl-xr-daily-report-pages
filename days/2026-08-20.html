PlayCanvas PR #9194 changes omni-light shadow-caster culling from six full scans to one classification pass, while PR #9195 exposes `shadowCascadeMask` on render components. Shadow cost and visibility regions become touchable masks. 5. Babylon.js PR #18814 improves Viewer Lite compatibility around environment blur / rotation, HDR cubemap skyboxes, shadow-only API, and hotspot camera orbit. Codrops' depth-map relighting article is a strong creative example for extending lighting, shadow, and viewpoint work from 2D images into dynamic surfaces.

注目事例と何が面白いかNotable example and why it matters

今日の注目は Codrops の depth-map relighting と three.js #34307/#34303 の組み合わせ。depth map relighting は、写真や平面画像を、法線・自己影・表面の凹凸を持つ動的な照明対象へ変える。そこへ RTTNode の resolutionScale と viewport sampling の安定化を重ねると、画像をただ照らすだけでなく、低解像度の照明 buffer、高解像度の輪郭 buffer、更新頻度の違う shadow buffer を意図的に見せられる。昨日の splat raycast は「どこを触っているか」を可視化したが、今日は「その場所がどの解像度・どの影カスケード・どの環境光で計算されているか」まで見せる方向。

The notable combination is Codrops' depth-map relighting with three.js #34307 and #34303. Depth-map relighting turns a photo or flat image into a dynamic lighting target with normals, self-shadowing, and surface relief. Adding RTTNode resolutionScale and stable viewport sampling lets us intentionally expose low-resolution lighting buffers, high-resolution edge buffers, and shadow buffers with different update rates. Yesterday's splat raycast visualized where the viewer touches; today's direction also shows which resolution, shadow cascade, and environment lighting are responsible for that point.

表現・インタラクションのアイデアExpression and interaction idea

短期案は「Depth Relight Shadow Budget Scope」。depth map 風の起伏を pointer light で照らし、mode 1 は relight、mode 2 は RTT resolutionScale の4段階 plate、mode 3 は omni shadow six-face culling、mode 4 は cascade mask、mode 5 は Viewer Lite 的な環境回転と hotspot orbit を表示する。クリック/Space は pass refresh pulse。中長期では、実画像 + depth map、WebGPU/TSL の RTTNode、PlayCanvas の shadowCascadeMask、Babylon Viewer の environment rotation を同じ uniform set に入れ、2Dビジュアルを照明設計ツール兼作品にする。

The short-term idea is Depth Relight Shadow Budget Scope. A depth-map-like relief is lit by pointer light; mode 1 shows relighting, mode 2 shows four RTT resolutionScale plates, mode 3 shows omni-shadow six-face culling, mode 4 shows cascade masks, and mode 5 shows Viewer Lite-style environment rotation and hotspot orbits. Click / Space sends a pass-refresh pulse. Longer term, a real image + depth map, WebGPU/TSL RTTNode, PlayCanvas shadowCascadeMask, and Babylon Viewer environment rotation can share one uniform set, turning a 2D visual into both a lighting-design tool and a piece.

制作に使えそうな技術メモProduction note

`RTTNode` の `resolutionScale` は、blur、refraction、shadow-like buffer、lighting cache の品質とコストを1つのパラメータで揃えやすい。`autoUpdate: false` にすると、pointer が止まった時だけ更新する、音のピーク時だけ更新する、視線が入った tile だけ更新する、といった演出に向く。ViewportTextureNode / backdrop sampling は WebGLRenderer 側で落ちないことが重要で、WebGPU 専用に閉じない試作が作りやすくなる。PlayCanvas の omni culling は、全6面を別々に検査する発想から一度分類して各 face へ配る発想へ変わった点が示唆的。影も splat sort と同じく、個別 pass の正しさより全体の分類・配分が効く。glTF normals 欠落時の flat shading は、データ不備を隠すより面の構造を見せる QA 表現として使える。

`RTTNode` `resolutionScale` gives one control for quality and cost across blur, refraction, shadow-like buffers, and lighting caches. With `autoUpdate: false`, updates can happen only when the pointer stops, on audio peaks, or for gaze-selected tiles. ViewportTextureNode / backdrop sampling staying stable on WebGLRenderer matters because prototypes do not have to be WebGPU-only. PlayCanvas omni culling is suggestive because it shifts from testing six faces separately to classifying once and distributing to faces. As with splat sorting, shadows benefit from global classification and allocation more than isolated pass correctness. Flat shading for glTF primitives without normals can also become QA expression that reveals face structure instead of hiding bad source data.

俯瞰メモBird's-eye memo

最近の傾向は、Gaussian Splat の sort / bounds / raycast、XR uniform / frustum / depth、MRT / OIT / MSAA、そして今日の RTT / shadow / relighting まで、内部 renderer state を隠すより見せる方向に寄っている。組み合わせ候補は、1. splat hit distance を depth relight の光源距離へ入れる、2. shadowCascadeMask を viewer の注視領域や音量で切る、3. RTT resolutionScale を Web Audio の帯域や FPS で変える、4. USD material graph / shader loader pending state を画面の色温度や blur として出す、の4つ。育てる価値が高いテーマは「作品に見える QA surface」。制作中は debug panel、公開時はインタラクション表現として機能する二面性がある。

The recent trend runs from Gaussian Splat sort / bounds / raycast, XR uniforms / frusta / depth, MRT / OIT / MSAA, to today's RTT / shadow / relighting: internal renderer state is increasingly useful when surfaced rather than hidden. Promising combinations are: 1. feeding splat hit distance into depth-relight light distance, 2. driving shadowCascadeMask from gaze or audio level, 3. changing RTT resolutionScale from Web Audio bands or FPS, and 4. turning USD material graph or shader-loader pending state into color temperature or blur. The theme worth growing is a QA surface that looks like a piece: a debug panel during production and an interaction layer in public.
