注目事例と何が面白いかNotable examples and why they matter

Cerebrium は WebGPU/TSL から WebGLRenderer + onBeforeCompile + ping-pong GPGPU + EffectComposer へ戻した制作判断が重要。見た目は同じでも noise、tone mapping、blend、lighting、UV interpolation、postprocess の差が積み上がるという記録は、前回までの engine parity diff の根拠になる。Dash Creative は fullscreen video texture を fragment shader で直接 UV remap し、カーソル中心の円形 ripple ではなく移動方向に伸びる歪みにしている点が使える。Trionn は GSAP/Three.js/Lenis/Web Audio を分離しつつ同期する話として、音反応を単なる beat ではなく scene state の一部として扱う参考になる。

Cerebrium is important because it documents a production move from WebGPU/TSL back to WebGLRenderer plus onBeforeCompile, ping-pong GPGPU, and EffectComposer. Its note that noise, tone mapping, blending, lighting, UV interpolation, and postprocess differences accumulate into different images supports the engine parity diff track. Dash Creative is useful because it remaps a fullscreen video texture directly in a fragment shader and stretches distortion along pointer movement direction rather than using a simple circular ripple. Trionn is a reference for keeping GSAP, Three.js, Lenis, and Web Audio decoupled but synchronized, treating audio reaction as scene state rather than a decorative beat.

制作に使えそうな技術メモProduction notes

方向付き歪みは、`uPointer` だけでなく `uVelocity` を smoothing/decay して渡すと hover ではなく drag/wake に見える。fragment shader 側では `dot(p - pointer, dir)` と縦方向成分を混ぜた sine を displacement にすると、波紋が円形に広がらず流れの向きを持つ。Babylon 9.19.0 の side-effect registration 修正は、ESM/pure import 構成で loader や postprocess が消える事故への警告として読む。three.js r185 の HTMLTexture 追従は、DOM 的な情報を canvas texture として扱う場合に API 変更へ備える必要がある。PlayCanvas/SuperSplat 側では、MSDF edge、8K export、SOG/GSplat renderer 差分を shader overlay で同時に見ると、作品確認と QA が分離しにくくなる。

Directional distortion feels like drag or wake rather than hover when `uVelocity`, not only `uPointer`, is smoothed and decayed into the shader. In the fragment shader, using a sine displacement based on `dot(p - pointer, dir)` plus a vertical component prevents a circular ripple and gives the wave a travel direction. Babylon 9.19.0's side-effect registration fix is a warning for ESM/pure import setups where loaders or postprocess modules may disappear. three.js r185's HTMLTexture API update means DOM-like information surfaces need to track API changes. On the PlayCanvas/SuperSplat side, viewing MSDF edges, 8K export pressure, and SOG/GSplat renderer differences through one shader overlay keeps artwork review and QA close together.

俯瞰メモBird's-eye memo

最近の傾向は、エンジン更新が単体機能ではなく「初期化、登録、fallback、表示差、検証 overlay」の問題としてつながっていること。Babylon の side-effect registration、Cerebrium の WebGPU から WebGL への移行、PlayCanvas の MSDF/GSplat 修正はすべて、production で shader graph や loader が期待通り動くかという同じ問題に見える。組み合わせると面白い要素は、方向付き歪み + 経路パルス + 空間音源 + MSDF readability。育てる価値が高いテーマは「状態の変化を UI ではなく場の残像として見せる」こと。短期は fullscreen shader で十分、中長期は実音声・実 splat・HTMLTexture 情報面へ置き換える。

The current pattern is that engine updates connect through initialization, registration, fallback, visual drift, and validation overlays rather than isolated features. Babylon's side-effect registration, Cerebrium's WebGPU-to-WebGL migration, and PlayCanvas MSDF/GSplat fixes all point to the same production question: whether shader graphs and loaders behave as expected. Promising combinations are directional distortion, path pulses, spatial sound sources, and MSDF readability. The theme worth growing is showing state changes as residual traces in the scene rather than as UI. A fullscreen shader is enough for short-term exploration; longer term, replace the synthetic parts with real audio, real splats, and HTMLTexture information surfaces.
