Babylon.js PR #18791 fixes WebGPU vertex layout pipeline cache key collisions, a quiet but important issue where offsets and merge boundaries change what the GPU actually sees.

注目事例と何が面白いかNotable examples and why they matter

今日の中心は PlayCanvas #9157。距離で LOD を落とすだけだと、細部が多いノードと近似しやすいノードを同じ扱いにしてしまう。error / cost / coverage で Pareto frontier を作る考え方は、レンダリングの最適化であると同時に、画面の中で「どこが情報を失っているか」を演出する方法になる。Codrops の WebGL タグでは Endless Interactive Glass Xylophone のような音と 3D 反応の事例が継続して見えるので、error priority を音階、打鍵、残響の強さへ割り当てると、品質配分が単なるデバッグ表示ではなく演奏可能な UI になる。

The key example is PlayCanvas #9157. Distance-only LOD treats a detail-heavy node and a near-duplicate node too similarly. Building a Pareto frontier from error, cost, and coverage is not just an optimization; it can become a way to show where information is being lost. Codrops' WebGL tag continues to surface audio-reactive 3D work such as the Endless Interactive Glass Xylophone, suggesting that error priority could map to pitch, strikes, and resonance so quality allocation becomes playable rather than merely diagnostic.

表現・インタラクションのアイデアExpression and interaction ideas

短期案は「Error Budget LOD Field」。画面を 5x4 の SOG node に分け、各 node に cost / error / coverage を持たせる。pointer に近いほど coverage が上がり、クリックや Space で budget pressure が入り、error/cost の高い node が発光して frontier line を描く。mode 2 は Gaussian Splat loader の fast path を帯状 stream として、mode 3 は particle gradient stop の sort を色点の整列として、mode 4 は GLSL Transpiler の preprocessor / array / loop をコード構造のリングとして描く。中長期では実 lod-meta.json、frame time、audio band、camera motion を同じ priority field に流す。

The short-term idea is Error Budget LOD Field. Split the screen into 5x4 SOG nodes, each carrying cost, error, and coverage. Pointer proximity raises coverage; click or Space injects budget pressure; high error/cost nodes glow and draw frontier lines. Mode 2 renders Gaussian Splat loader fast paths as streaming bands, mode 3 sorts particle gradient stops as colored control points, and mode 4 renders GLSL Transpiler preprocessor / array / loop structures as code rings. Longer term, feed real lod-meta.json, frame time, audio bands, and camera motion into the same priority field.

制作に使えそうな技術メモProduction notes

SOG LOD の error metadata は、品質を距離だけでなく「その node を粗くすると何を失うか」で扱える点が強い。実装では cost と error の frontier を作り、coverage * benefit / cost を priority にする発想が使える。three.js 側の #34205/#34210 は、splat 表現を見せる前のロード時間と bundle size を削る話で、体験設計では最初の数秒の密度・欠落・補間の見せ方に直結する。GLSL Transpiler の #34206/#34208 は、#define、#ifdef、配列 palette など、古い fragment shader で多用される構文を保ったまま移植しやすくする。Babylon の gradient sort は、UI 上の stop 順序と GPU LUT のピクセル順がずれると見た目が破綻するという、小さいが制作現場では大きい論点。

SOG LOD error metadata is powerful because quality is no longer only distance-based; it can represent what is lost when a node becomes coarse. In implementation terms, build cost/error frontiers and rank upgrades by coverage * benefit / cost. three.js #34205/#34210 reduce load time and bundle size before splats are even visible, which affects how the first seconds of density, gaps, and interpolation feel. GLSL Transpiler #34206/#34208 make it easier to carry old fragment shader habits like #define, #ifdef, and array palettes forward. Babylon's gradient sort shows a small but production-critical issue: if editor stop order diverges from GPU LUT pixel order, the image breaks.

サンプルデータの可能性と組み合わせ考察Possibilities for the sample data and combinations

今日のサンプルは pointer、mode、pressure、time を入力にし、node priority、frontier line、stream band、gradient stop、code ring を描画状態として持つ。データとして見ると、ユーザーがどの node に coverage を与えたか、pressure 時にどの error/cost の組が選ばれたか、gradient stop がどの程度秩序化されたかを記録できる。展示では、観客の位置を coverage、音量を budget、映像の動き量を error にして、空間全体が品質配分を演奏する構成にできる。WebXR では、視線中心の node だけ error frontier を上げ、周辺は粒度を下げる foveated 演出へつなげられる。ブランド/エンタメでは、loading や LOD を隠す代わりに、優先度が走査して素材が選ばれていく「制作機械の内側」として見せると相性が良い。

Today's sample uses pointer, mode, pressure, and time as inputs, with node priority, frontier lines, stream bands, gradient stops, and code rings as render states. As data, it can record which nodes received coverage, which error/cost pairs were selected under pressure, and how strongly gradient stops became ordered. In installations, audience position can drive coverage, volume can drive budget, and video motion can drive error so the space performs quality allocation. In WebXR, raise the error frontier around gaze and lower peripheral granularity for a foveated expression. For brand or entertainment work, instead of hiding loading and LOD, show priorities scanning and choosing assets as the inside of a production machine.
