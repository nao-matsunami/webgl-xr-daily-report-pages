1. three.js issue streamでは、9月17-18日に WebGPURenderer のdepth-stencil sampling、transparent Line2リサイズ時の使用中texture破棄、WebGL2 fallbackのGL program / shader / VAO破棄漏れ、GTAONode depth multisampled texture compile問題が並んでいる。9/19-20のocclusion / framegraph / VATから、今日は「深度textureの寿命とfallback資源の後始末」を表現入力として扱う。2. three.js migration guide の 186→187 には、PMREMがcube render targetベースになり CubeUVReflectionMapping が削除されること、WebGPURenderer / WebGLRendererがWeakRef / FinalizationRegistryを内部利用すること、XR camera行列やrender target bound時のviewport/scissor pixel ratioの変更が出ている。3. PlayCanvas Engine v2.22.2はshadow cascade count変更時のshader選択とStandardMaterial map iteration修正が中心。v2.22.0には SceneDepthReader、multisampled depth resolve、custom MSAA resolve、WireRenderer、SOG / GSplat LODなどが大きくまとまっている。4. npm上では playcanvas 2.23.0-beta 系も更新されており、v2.22の深度・MSAA・SOG基盤の次を追う対象になる。5. Babylon.js 9.26.xでは OpenUSD WebAssembly scene loader、Inspector Lite text / sprite layer、KHR_interactivity Phase 1、mesh blending post process、Gaussian splatting coarse-first streaming、USD materials / instancing / skinning改善が続いている。USD loaderはOpenUSD/WASM workerがstageをcomposeし、command queueとdata bufferをBabylon.js sceneに変換する構造なので、今日の派生試作はここをステージキューとして可視化した。

注目事例と何が面白いかNotable examples and why they matter

Babylon.js's USD loader has a clear pipeline: USD asset to OpenUSD/WASM worker to binary command buffers to scene. That connects directly to September 6's USD worker stage scan, September 18's splat stream worker, and September 20's frame-graph audio mixer. The three.js depth-stencil / PMREM / fallback leak issues are not glamorous features, but they can turn failures in transparent lines, reflections, AO, XR viewpoints, and resize behavior into a staged failure language.

制作に使えそうな技術メモProduction notes

depth lifecycle系は `depthFormat`, `stencilMask`, `sampleCount`, `textureAge`, `resizeGeneration`, `compileId`, `destroyQueued`, `fallbackBackend`, `liveProgramCount`, `liveVaoCount` をログ化すると、本物のrenderer状態に差し替えやすい。PMREM / reflection系は `cubeFace`, `mipLevel`, `roughness`, `mappingKind`, `disposedAtFrame`, `xrCameraSourceEye` を持つと、r187移行のcube render target化やXR camera変更を可視化できる。USD / SOG系は `stageId`, `commandOffset`, `payloadBytes`, `meshCount`, `materialCount`, `skeletonCount`, `tileId`, `coarseReady`, `refineReady`, `lodError`, `cameraBudget`, `inspectorWarning` を共通state textureへ詰めるとよい。

For depth lifecycle work, logging `depthFormat`, `stencilMask`, `sampleCount`, `textureAge`, `resizeGeneration`, `compileId`, `destroyQueued`, `fallbackBackend`, `liveProgramCount`, and `liveVaoCount` makes it easy to swap in real renderer state later. PMREM / reflection work should carry `cubeFace`, `mipLevel`, `roughness`, `mappingKind`, `disposedAtFrame`, and `xrCameraSourceEye` so the r187 cube-render-target transition and XR camera changes can be visualized. USD / SOG work can pack `stageId`, `commandOffset`, `payloadBytes`, `meshCount`, `materialCount`, `skeletonCount`, `tileId`, `coarseReady`, `refineReady`, `lodError`, `cameraBudget`, and `inspectorWarning` into a shared state texture.
