注目事例と何が面白いかNotable examples and why they matter

Infinite Liquid Glass Grid の面白さは、ガラスを MeshPhysicalMaterial や本物の厚いジオメトリで作らず、flat plane の shader 内で距離場、height、normal、refraction を作るところにある。しかも動画テクスチャ自身を曲げるため、scene capture や transmission 用 render target を避けられる。これは #34479 の bilinear fetch と同じく、重い処理を減らして、その分を動きや量へ戻す設計。Drawing With Light は逆に、flat な meshline を「光を受ける tube」へ戻している。両者を並べると、今週の大きな傾向は flat / line / debug lane のような安い表面に、厚み・法線・遅延・履歴を与えて立体的な体験にすることだと見える。

The interesting part of Infinite Liquid Glass Grid is that it avoids MeshPhysicalMaterial and heavy glass geometry, building distance fields, height, normals, and refraction inside the shader on flat planes. Because it bends each card's own video texture, it avoids scene capture and transmission render targets. Like #34479's bilinear fetch optimization, it removes heavy work and spends the budget on motion and quantity. Drawing With Light goes the other way: it turns flat meshline-like strokes back into lit tubes. Together they show this week's pattern: give cheap surfaces such as planes, lines, and debug lanes thickness, normals, delay, and history until they become spatial experiences.

制作に使えそうな技術メモProduction notes

fake glass は、2D SDF から edge distance を作り、近傍差分で normal を推定し、その normal で video / image / procedural texture のUVをずらすだけでも成立する。重要なのは、全部を postprocess に逃がさず、material 側の quality knob として tap数、bevel幅、dispersion、rim幅を持つこと。tube 系は CPU mesh rebuild を避け、progress / angle / instanceIndex / buffer offset を attribute にして vertex shader 側で形を決めると、音反応や pointer 反応を uniform で済ませられる。readback 系は SceneDepthReader / Picker の結果を毎フレーム使うと staging buffer churn が見えやすいので、pool の有無を telemetry として可視化しておく価値がある。three.js r187 の setViewport / setScissor 変更は render target 座標の pixel ratio 前提を崩すため、read rect、mini viewport、bloom mip、XR eye viewport を同じ正規化座標に揃えるチェックを入れたい。

Fake glass can work with a 2D SDF edge distance, finite-difference normals, and UV displacement of video, image, or procedural textures. The key is to keep quality knobs in the material, such as tap count, bevel width, dispersion, and rim width, instead of hiding everything in postprocessing. For tubes, avoid CPU mesh rebuilds by storing progress, angle, instanceIndex, and buffer offsets as attributes and deciding the shape in the vertex shader; audio and pointer response can then be uniform-driven. For readback, SceneDepthReader / Picker every frame can expose staging buffer churn, so visualizing pool state as telemetry is useful. The three.js r187 setViewport / setScissor change affects render-target pixel-ratio assumptions, so read rectangles, mini viewports, bloom mips, and XR eye viewports should be checked against one normalized coordinate convention.

サンプルデータの可能性と組み合わせ考察Possibilities for the sample data and combinations

今日の2本は、入力値と状態ログをそのまま素材化しやすい。1本目は pointer、pulse、mode、probe progress、疑似cell id をデータ化できる。展示では来場者の移動や音量でglass thicknessが変わり、焼けた領域だけ映像が読みやすくなる構成にできる。2本目は Inspector count、readback size、pool hit/miss、transpilation enabled、tap count、GPU duration を入れると、運用時の異常を美術的な変化として出せる。組み合わせるなら、Web Audio の low band = probe warmth、mid band = cloth viscosity、high band = chromatic dispersion、カメラ/MediaPipe = dirty region、WebXR depth = readback lane、過去の日次サンプル = card texture がよい。

Both samples can turn inputs and state logs directly into material. The first can record pointer, pulse, mode, probe progress, and pseudo cell id. In an installation, visitor movement or volume could change glass thickness, while baked regions reveal video more clearly. The second can ingest Inspector count, readback size, pool hit/miss, transpilation enabled, tap count, and GPU duration, making runtime anomalies visible as artwork. Strong combinations: Web Audio low band for probe warmth, mid band for cloth viscosity, high band for chromatic dispersion, camera/MediaPipe for dirty regions, WebXR depth for readback lanes, and past daily samples as card textures.
