表現・インタラクションのアイデアExpression and interaction ideas

本命は『Version-Gated Light Score』。pointer を編集フロンティア、click/Space を attribute version 更新として、source→changed range→afterglow→composite を切替表示する。派生は『GPU Task Latency Weave』で、queue/pending/available/readback を織物の横糸として扱う。短期では pointer velocity、audio onset、scroll の dirty range だけで成立する。中長期では `attributeVersion`, `updateRangeStart`, `updateRangeCount`, `uploadBytes`, `taskStart`, `taskEnd`, `queryState`, `droppedTasks` を共通state textureへ記録し、観客の注視・音・到着したLODを同じ譜面に置く。

Use an edit frontier and a version pulse now; later connect attribute ranges, GPU task states, audio and LOD arrival through one state texture.

制作に使えそうな技術メモProduction note

dynamic attribute は `version` と dirty range を対にして記録し、version が不変なら upload も発光も行わない。index update は描画範囲・topology と結び付くため、更新点を丸ではなく線・切れ目・群れの分岐として見せると意味が明快になる。GPU timer は pending と available を混ぜず、readback が遅れたフレーム番号も保存する。Babylon Lite のように、CPU側の draw count と非同期GPU readbackを同じフレームだと誤認しない。WebGL fallback は `performance.now()` を推定時間として別色にし、実GPU計測ではないことを保つ。

Log version and dirty ranges together; keep pending GPU reads distinct from available samples, and label WebGL wall-clock estimates honestly.

俯瞰メモBird's-eye memo

10月末から11月初めにかけて、compile、shadow、LOD、radiosity、timestampを『準備→到着→残響』で扱ってきた。今回の version gate は、その間に『何が変わったか』という編集点を与える。`gaze + audio onset + attributeVersion + dirtyRange + uploadBytes + taskState + lodArrival + historyAge` を共通scoreにすれば、重い3Dシーンでも変化した場所だけが観客の注意を先取りできる。これは展示の反応面、音楽ライブの照明、更新の多いデータ空間に育てる価値が高い。

A version gate supplies the missing edit point in the prepare-arrive-afterglow arc; it is a strong long-term bridge across installations, live light and changing data spaces.
