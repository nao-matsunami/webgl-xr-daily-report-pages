今日の重要トピックKey topics today

1. Babylon.js PR #18784 は WebGPU render-target bind ごとの `GPUTexture.createView()` を cache 化し、texture view の増殖を抑える。昨日の capability guard から一歩進み、今日は resource lifetime を画面上の熱量として扱う価値が見えた。2. Babylon.js PR #18785 は Babylon Lite Viewer に WebGPU device-lost recovery をつなぎ、GPU reset や tab backgrounding 後の blank/frozen canvas を復帰対象にした。3. Babylon.js PR #18782 / #18779 / #18778 は WebGPU XR に CPU depth sensing、quad layer path、AR projection texture clear を追加・修正しており、depth、compositor layer、clear が同時に進んでいる。4. three.js PR #34166 は DirectRenderPipeline を merge し、中間 framebuffer と output pass を避ける opt-in 経路を入れた。PR #34181 は TSL struct storage buffer の1要素/複数要素で WGSL interface が変わる問題を、常に array として扱う方向にしている。5. PlayCanvas PR #9156 は UI image の triangle strip を indexed triangles に変える提案。特定 Android GPU で quad の片側だけ UV が壊れる話は、トポロジーと driver artifact をそのまま視覚表現にできる。

1. Babylon.js PR #18784 caches WebGPU texture views instead of calling `GPUTexture.createView()` on every render-target bind, reducing runaway resource churn. After yesterday's capability guards, resource lifetime itself becomes a useful visual signal. 2. Babylon.js PR #18785 wires WebGPU device-lost recovery into the Lite Viewer, addressing blank or frozen canvases after GPU reset or memory pressure. 3. Babylon.js PRs #18782 / #18779 / #18778 advance WebGPU XR CPU depth sensing, quad layers, and AR projection texture clearing. 4. three.js PR #34166 merged DirectRenderPipeline as an opt-in path that avoids the intermediate framebuffer and output pass, while #34181 works on keeping TSL struct storage buffers array-shaped even at length one. 5. PlayCanvas PR #9156 proposes replacing UI image triangle strips with indexed triangles. A one-half UV corruption on a specific Android GPU is exactly the kind of topology / driver artifact that can become an expressive diagnostic.

注目事例と何が面白いかNotable example and why it matters

PlayCanvas PR #9156 is interesting because the bug has a clear visual shape: only the second triangle of a strip corrupts UV interpolation, producing a diagonal smear across the quad. This is more than a UI fix; it is a teaching artifact showing that the same rectangle has different GPU meaning depending on topology. Like Codrops' Ridgeline turns DEM terrain into a live Three.js surface, this turns abstract implementation structure into something inspectable.

表現・インタラクションのアイデアExpression and interaction idea

短期案は「Resource Lifetime Topology Scope」。4レーンを用意し、1 は texture view leak と cache gate、2 は device-lost recovery の復帰波、3 は DirectRenderPipeline の中間 framebuffer bypass、4 は triangle strip の対角 smear と indexed triangles の安定化を表す。ドラッグで lifetime lane を曲げ、クリック/Space で pressure を注入する。中長期では、Babylon の texture view cache hit/miss、WebGPU device-lost event、three.js direct path on/off、PlayCanvas topology type を実ログとして流し込む。

The short-term idea is Resource Lifetime Topology Scope. Four lanes represent texture-view leaks and cache gates, device-lost recovery waves, DirectRenderPipeline bypassing an intermediate framebuffer, and triangle-strip diagonal smear versus indexed-triangle stability. Drag bends the lifetime lanes, and click or Space injects pressure. Longer term, feed it real Babylon texture-view cache hits/misses, WebGPU device-lost events, three.js direct-path state, and PlayCanvas topology types.

制作に使えそうな技術メモProduction note

WebGPU の resource lifetime は、フレーム単位の見た目には出にくいが、長時間体験や展示では最重要の品質になる。texture view、sampler、bind group、pipeline の cache hit/miss をカウンタ化し、一定値を超えたら visual heat として出すと、作品の演出と QA が重なる。device-lost recovery は、復帰前後の asset reload / rebind / shader warmup を段階表示にするとユーザーに不安を与えにくい。DirectRenderPipeline は速く見える一方、blending と framebuffer sampling の制約を持つので、postprocess 前提の作品では bypass lane と fallback lane を明示する。triangle strip 問題は、UI だけでなく glTF `mode: 5` のような geometry import でも watch 対象にできる。

WebGPU resource lifetime rarely appears in a single frame, but it is critical for long-running experiences and installations. Count cache hits and misses for texture views, samplers, bind groups, and pipelines; when a threshold is crossed, expose it as visual heat so expression and QA overlap. Device-lost recovery can be shown in stages: asset reload, rebind, and shader warmup. DirectRenderPipeline can be faster, but blending and framebuffer-sampling constraints mean postprocess-heavy work should expose bypass and fallback lanes. Triangle-strip issues are worth watching not only in UI but also in imported geometry such as glTF `mode: 5`.

俯瞰メモBird's-eye memo

最近の傾向は、WebGPU/XR/GSplat そのものより、その周辺の「壊れ方」と「復帰の仕方」が表現素材になっていること。clear、guard、mask、hidden state に続き、今日は cache、device-lost、direct path、topology が加わった。組み合わせると面白いのは、KHR_interactivity の pointer event が capability を開閉し、DirectRenderPipeline が bypass/fallback を切り替え、texture view cache heat が背景の粒度を変え、triangle topology が UI や画像面の歪みとして出る構成。中長期で育てる価値が高いテーマは「runtime diagnostics as visual language」。単なる debug overlay ではなく、作品やブランド演出の品質感を支える視覚文法にできる。

The recent trend is that the failures and recovery behavior around WebGPU, XR, and GSplat are becoming stronger expressive material than the big technologies themselves. After clear, guard, mask, and hidden state, today's additions are cache, device-lost, direct path, and topology. A promising combination is KHR_interactivity pointer events opening and closing capabilities, DirectRenderPipeline toggling bypass and fallback, texture-view cache heat changing background density, and triangle topology appearing as distortion on UI or image surfaces. The high-value mid-term theme is runtime diagnostics as visual language: not just a debug overlay, but a visual grammar that supports the perceived quality of an artwork or branded experience.
