制作に使えそうな技術メモProduction note

TSL / node material の branch bug は、shader authoring で `if` を避ければよい話ではない。共通式を temp に落とす最適化、flow code の emission 位置、条件分岐内の再参照が絡むため、制作ツール側では「どの node がどの branch で評価済みか」を可視化する QA が必要になる。WebGPU clipping + stencil は、clip されたピクセルを消すだけでなく、clip されたが計算済み、visible だが stale、coverage だけ残る、といった状態に分けられる。Babylon.js の MultiTexture は、RawTexture2DArray を使うので WebGL2+ 前提だが、layer index をアニメーションさせるだけで material variation / posterization / glitch にしやすい。PlayCanvas alphaToCoverage は、透明境界を単純な alpha blend ではなく sample coverage に落とすので、粒状の edge 表現に向く。

The TSL / node-material branch bug is not just a matter of avoiding `if` in shader authoring. Optimization to shared temps, flow-code emission placement, and repeated references inside conditionals interact, so production tools need QA that shows which node has been evaluated in which branch. WebGPU clipping + stencil is not only about discarding clipped pixels; states such as computed-but-clipped, visible-but-stale, and coverage-only can be separated. Babylon.js MultiTexture uses RawTexture2DArray, so it assumes WebGL2+, but animating layer indices alone can produce material variation, posterization, and glitch. PlayCanvas alphaToCoverage maps transparent boundaries into sample coverage rather than simple alpha blend, making it useful for granular edges.
