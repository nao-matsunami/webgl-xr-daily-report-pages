GPUリソース寿命、MSAA texture、retroreflectionを触れる状態面にする

Turning GPU resource lifetime, MSAA textures, and retroreflection into touchable state surfaces

three.js の `Renderer.dispose()` 非同期化、dynamic shadow map size 追跡、WebGPU fallback のオンデマンド化、PlayCanvas の multisampled Texture API / MSAA binding / parallax mip level、Babylon.js の KHR_materials_retroreflection / overlay texture binding leak / MultiTexture / GSplat opacity roulette を、前回の TSL 検証レーンと layer scope から「寿命、sample、反射、binding を演出状態として見せる」方向へ進めた。本命サンプルとして Async Dispose Lifetime Scope、派生サンプルとして Retroreflective Cone Probe を実装した。

Today connects three.js asynchronous `Renderer.dispose()`, dynamic shadow-map-size tracking, and on-demand WebGPU fallback loading; PlayCanvas multisampled Texture API, MSAA bindings, and parallax mip-level sampling; and Babylon.js KHR_materials_retroreflection, overlay texture binding leak fixes, MultiTexture, and GSplat opacity roulette to yesterday's TSL validation lanes and layer scopes. The direction is to expose lifetime, samples, reflection, and bindings as performance state. Two samples were implemented: Async Dispose Lifetime Scope and Retroreflective Cone Probe.

今日の重要トピックKey topics today

1. three.js PR #34364 は `Renderer.dispose()` と `Backend.dispose()` を非同期化し、timestamp query pool など GPU resource の解放を await できるようにする変更。内部 teardown order も明示され、前回までの offscreen suspension / resource lifetime の話と直結する。2. three.js PR #34360/#34361 は WebGPURenderer 側で shadow map size の動的変更を検出し、NodeMaterialObserver へ追跡を寄せる流れ。shadow atlas を固定前提にせず、サイズ変更そのものを状態として扱う材料になる。3. PlayCanvas PR #9217 は `new Texture(device, { samples: 4 })` のように WebGPU multisampled texture を first-class にし、#9167 の multisampled binding と合わせて sampleIndex を shader 表現へ持ち込む足場を作った。#9219 は parallax occlusion march を明示 mip level で読むことで、遠景の aliasing と texture cache の問題を抑える。4. Babylon.js PR #18829 は draft の `KHR_materials_retroreflection` を OpenPBRMaterial として読む実装。交通コーンのような camera-adjacent light で強く返る材質は、Web上の安全・案内・演出UIに向いている。#18828 は overlay texture binding が shared PBR material に漏れる問題で、binding state の汚染を視覚化する題材として面白い。5. Codrops の HAOQI.DESIGN 事例は DOM/CSS/WebGL を一つの retro-futurist stage にしており、renderer内部の状態をUIではなく舞台装置にする流れを補強している。

1. three.js PR #34364 makes `Renderer.dispose()` and `Backend.dispose()` asynchronous so GPU resources such as timestamp query pools can be awaited during release. It also clarifies teardown order, directly extending the recent offscreen-suspension and resource-lifetime thread. 2. three.js PR #34360/#34361 detect dynamic shadow-map-size changes in WebGPURenderer and move tracking toward NodeMaterialObserver. This treats shadow-atlas resizing itself as a state surface. 3. PlayCanvas PR #9217 makes WebGPU multisampled textures first-class via `new Texture(device, { samples: 4 })`; together with #9167, this brings sampleIndex into shader expression. #9219 samples parallax occlusion marching at an explicit mip level to reduce minification aliasing and texture-cache pressure. 4. Babylon.js PR #18829 implements the draft `KHR_materials_retroreflection` as OpenPBRMaterial. Materials that return light strongly toward a camera-adjacent lamp, like a traffic cone, are useful for web safety, guidance, and entertainment cues. #18828 fixes overlay texture bindings leaking into shared PBR materials, which is a good subject for visualizing binding-state contamination. 5. Codrops' HAOQI.DESIGN case study reinforces the direction of turning DOM/CSS/WebGL into one stage rather than a UI around a renderer.

注目事例と何が面白いかNotable examples and why they matter

今日の核は「片付ける瞬間を見せる」こと。WebGL/WebGPUの作品は生成や描画の瞬間ばかり見せがちだが、`dispose()`、query pool、fallback import、shadow map resize、offscreen resume は、実運用では体験の滑らかさを決める重要な時間軸になる。ここに retroreflection を足すと、暗い面から急に戻る反射や、binding leak で意図しない texture が残る状態を、単なるバグ表示ではなく演出上の「残光」「汚染」「回収」として扱える。PlayCanvas の multisampled texture は、同じ pixel 内に複数の記憶を持たせる方向でこの話に接続できる。

The strongest theme today is showing the cleanup moment. WebGL/WebGPU works often emphasize creation and rendering, but `dispose()`, query pools, fallback imports, shadow-map resizing, and offscreen resume are critical timelines for real-world smoothness. Adding retroreflection turns sudden light return, or accidental texture leftovers from binding leaks, into afterglow, contamination, and recovery rather than only bug displays. PlayCanvas multisampled textures connect by allowing one pixel to hold multiple memories.

制作に使えそうな技術メモProduction notes

`dispose()` が async になる場合、単に戻り値を Promise にするだけでなく、UI/scene切替側も破棄待ち、次scene生成、GPU query pool回収、fallback backend teardown の順序をログ化した方がよい。PlayCanvas #9217 では multisampled texture が 2D、non-array、non-storage、mipmapなし、初期dataなしなどの制約を持つため、実サンプル化する時は通常textureと同じasset pipelineに載せない。#9167 の WGSL reflection と組み合わせると `texture_multisampled_2d` を user shader から読む設計になる。Babylon #18829 の retroreflection は camera-light-view の角度依存を作品側のインタラクションへ転用しやすい。#18828 のような binding leak は shared material と outline/pass 切替の間で起きるため、debug view では material id、effect id、bound texture id を同じ画面に出すと原因が見つけやすい。

If `dispose()` becomes async, the scene/UI layer should log disposal wait, next-scene creation, GPU query-pool collection, and fallback-backend teardown order rather than just accepting a Promise return. PlayCanvas #9217 multisampled textures are constrained to 2D, non-array, non-storage, no mipmaps, and no initial data, so they should not be pushed through the same asset pipeline as ordinary textures. Combined with #9167 WGSL reflection, user shaders can read `texture_multisampled_2d`. Babylon #18829 retroreflection makes camera-light-view angle dependence easy to reuse as interaction. Binding leaks like #18828 happen between shared materials and outline/pass changes; debug views should show material id, effect id, and bound texture id together.

俯瞰メモBird's-eye memo

最近の傾向は、renderer の正しさだけでなく lifecycle の正しさが表現素材になってきたこと。8/21 の fog buffer、8/22 の branch/layer/stencil、8/23-24 の TSL unit test / MultiTexture に、今日の async dispose と retroreflection を重ねると、「生成、検証、描画、反射、破棄」が一本の時間軸になる。組み合わせ候補は、MSAA sampleごとに異なる resource lifetime を持たせ、破棄されていない sample だけ retroreflective に光る表現。育てる価値が高いテーマは、WebGL/WebGPU の内部状態を観客が触れる舞台照明として扱うこと。カードUI系ではなく、空間演出、パーティクル、ポストプロセス、音反応へ接続しやすい。

The recent trend is that renderer lifecycle correctness, not only rendering correctness, is becoming expressive material. Combining the 8/21 fog buffer, 8/22 branch/layer/stencil, 8/23-24 TSL unit tests / MultiTexture, and today's async dispose / retroreflection creates one timeline: create, validate, render, reflect, dispose. A strong combination is to give each MSAA sample a different resource lifetime and make only non-disposed samples retroreflective. The theme worth growing is treating WebGL/WebGPU internal state as stage lighting that viewers can touch. This connects better to spatial staging, particles, postprocess, and audio reaction than to card UI.

サンプルデータの可能性と組み合わせ考察Possibilities for the sample data and combinations

今日の2サンプルは、resource id、dispose開始/終了時刻、query pool数、sample count、light vector、reflection intensity、binding leak発生をデータ化できる。展示なら、観客が近づくほど retroreflective layer が強く返り、裏側では不要resourceが消えていく「片付く光」の壁にできる。Webサイトなら、scrollで offscreen viewer を止め、復帰時のdelta spikeを光の残像で見せる。音反応なら、低域を dispose pulse、中域を query lane、高域を retroreflection band に割り当てる。WebXRなら、左右眼の sampleIndex に別々の lifetime を持たせ、片眼だけ残るbinding leakを空間的な違和感として出せる。MediaPipeを足す場合は、手の距離を headlight、指の本数を sample count、手の開閉を resource release に割り当てると、GPU内部の管理語彙を身体で演奏できる。

The two samples can turn resource id, dispose start/end time, query-pool count, sample count, light vector, reflection intensity, and binding leak events into data. In an installation, approaching visitors could strengthen retroreflective layers while unused resources disappear behind the scene, creating a wall of cleanup light. On a website, scroll can suspend offscreen viewers and show resume delta spikes as afterimages. For audio reaction, map bass to dispose pulse, mids to query lanes, and highs to retroreflection bands. In WebXR, give each eye's sampleIndex a different lifetime and show one-eye binding leaks as spatial tension. With MediaPipe, hand distance can be the headlight, finger count the sample count, and hand open/close the resource release gesture.
