注目事例と何が面白いかNotable examples and why they matter

PlayCanvas の Grace Cathedral は、WebGPU では compute で splat を cull/project/sort し、WebGL2 では CPU worker sort に戻すという実装差を持ちながら、同じ体験として成立させている点が引き続き重要。今回の PlayCanvas PR 群は、このような二系統レンダリングの足場をさらに細かく整えている。Babylon.js の GS sort padding 問題は、パフォーマンスのための配列都合がそのまま見た目に漏れる例で、診断ビューでは「padding residue」を色にしておく価値がある。Codrops の infinite gallery は 3D ではないが、無限ループ、parallax、flip transition を同じ時間値で束ねる発想が、SOG chunk や LOD の入れ替わりを見せる timeline UI に転用できる。

PlayCanvas' Grace Cathedral remains important because it maintains one experience while using WebGPU compute for splat cull/project/sort and a WebGL2 CPU-worker sort fallback. The recent PlayCanvas PRs refine the foundation for that dual-rendering approach. Babylon's GS sort padding issue shows how array padding decisions made for performance can leak directly into the image; a diagnostic view should color that as padding residue. Codrops' infinite gallery is not 3D, but its shared time value for loop, parallax, and flip transitions can transfer to timeline views for SOG chunks and LOD swaps.

制作に使えそうな技術メモProduction notes

MRT を使うときは、最初から G-buffer を作るより、color / id / coverage / artifact heat の小さな4出力で始めると検証しやすい。PlayCanvas の independent blending は attachment ごとに蓄積の意味を変えられるので、発光色は加算、ID は上書き、coverage は最大値、heat は別ブレンドのような設計がしやすくなる。per-attachment clear color は、クリック位置だけ attachment の初期値を見せる inspect 表現に向く。TransformFeedback の複数 buffer は、WebGL2 側でも particle/splat の current state と previous state を分ける用途に使える。three.js WebGPU/WebXR の MSAA・single-pass・multiview は、ポストプロセス前の resolve が見た目を決めるため、glow や霧の細線は片目単位で確認する必要がある。Babylon の side-effect registration は、tree-shaking 後の loader/postprocess/audio smoke test を制作テンプレートに入れるべき合図。

For MRT work, start with four small outputs such as color, id, coverage, and artifact heat before building a full G-buffer. PlayCanvas independent blending lets each attachment accumulate differently: additive glow color, overwritten IDs, max coverage, and separately blended heat. Per-attachment clear colors are useful for pointer-based inspection that exposes an attachment's initial value. Multiple TransformFeedback buffers are also useful on WebGL2 for separating current and previous particle or splat state. In three.js WebGPU/WebXR, MSAA, single-pass, and multiview determine resolve before post-processing, so thin glow and fog lines need per-eye checks. Babylon's side-effect registration fixes are a signal to include loader, postprocess, and audio smoke tests after tree-shaking.

サンプルデータの可能性と組み合わせ考察Possibilities for the sample data and combinations

今日のサンプルは、入力値として pointer、drag velocity、pressure、mode を持ち、描画状態として color/id/fog/sortPadding の4チャンネルを持つ。この4チャンネルを実データに置き換えると、展示では来場者の視線・手の動きで空間の霧や奥行き破綻が露出するビューア、Web演出では商品や建築 splat の品質診断をそのままビジュアルにするランディング、音反応では低域を fog density、中域を refraction、高域を padding residue の瞬きへ割り当てられる。WebXR では左右眼の差分を id/fog attachment に入れ、MediaPipe では手の開閉を clear lens の半径へ入れると、診断情報と身体入力が接続できる。

Today's sample has pointer, drag velocity, pressure, and mode as inputs, and color/id/fog/sortPadding as four render-state channels. Replacing those channels with real data could become an installation viewer where gaze or hand motion reveals fog and broken depth, a web experience where product or architectural splat quality diagnostics become the visual design, or an audio-reactive scene where bass controls fog density, mids control refraction, and highs trigger padding-residue flicker. In WebXR, left/right-eye differences could feed id/fog attachments; with MediaPipe, hand openness could control the clear-lens radius, connecting diagnostics to body input.
