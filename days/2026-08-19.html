The short-term idea is Splat Group Raycast Scatter Scope. 制作に使えそうな技術メモProduction note

Gaussian Splat の複数メッシュ合成では、各 mesh が内部で back-to-front に正しく sort されていても、mesh 間の順序は別問題になる。作品では、複数レイヤーを独立 pass で重ねると境界だけ不自然になることがあるため、scene-level order / shared buffer / single draw という観点を早めに設計へ入れるとよい。raycasting は hit 表示だけでなく、splat の密度、SH degree、bounds、sort bucket を inspect する入口になる。PlayCanvas の particle bounds 再計算は、spawn volume や音反応パーティクルを使う場合の clipping / culling 表現に直結する。Babylon の shader loader abstraction と KHR_materials_scatter は、散乱・肌・蝋・霧のような半透明感を engine 依存の実装から少し切り離して考える材料になる。

For multiple Gaussian Splat meshes, each mesh can be internally back-to-front sorted while inter-mesh ordering remains wrong. In production, independent passes can create unnatural seams at overlaps, so scene-level order, shared buffers, and single-draw thinking should enter the design early. Raycasting is not just hit display; it can inspect density, SH degree, bounds, and sort buckets. PlayCanvas particle-bounds recalculation maps directly to clipping and culling behavior for spawn-volume or audio-reactive particles. Babylon's shader-loader abstraction and KHR_materials_scatter help think about scattering, skin, wax, and fog-like translucency with less engine-specific coupling.
