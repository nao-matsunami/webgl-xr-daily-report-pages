注目事例と何が面白いかNotable examples and why they matter

今日の核は PlayCanvas #9174/#9175。従来の depth prepass は opaque mesh に強く、splat のような半透明雲には硬すぎる。forward pass の premultiplied blending と同時に depth を積むと、色だけでなく soft depth も得られる。これは「写っているのに霧やDOFには存在しない」問題を減らすだけでなく、半透明の存在感を depth contour、fog gate、selection halo として演出できる。three.js #34250 の attachment 別 clear は、この depth / id / mask / color を別々の初期色で舞台装置化する入口になる。

The core item is PlayCanvas #9174/#9175. A traditional depth prepass works well for opaque meshes but is too hard for semi-transparent splat clouds. Accumulating depth during the forward premultiplied blend yields soft depth alongside color. This does more than fix the issue where splats are visible but absent to fog or DOF; it lets semi-transparent presence become depth contours, fog gates, and selection halos. three.js #34250's per-attachment clear colors become an entry point for staging depth, ID, mask, and color buffers as separate lighting channels.

表現・インタラクションのアイデアExpression and interaction ideas

短期案は「MRT Depth IBL Telemetry」。4つの attachment を縦の発光プレートとして出し、clear 色、depth contour、IBL caps、particle async packet を 1-4 キーで切り替える。pointer は attachment の位相と soft depth の流れを曲げ、Space / hold は budget pressure を入れる。中長期では、実 WebGPU timestamp query、MRT clear color、scene depth producer、IBL fallback、particle material build state を同じ telemetry texture に詰める。鑑賞者には抽象的な舞台照明に見えるが、裏では実際のレンダリング状態を反映している、という構造に育てたい。

The short-term idea is MRT Depth IBL Telemetry. Four attachments become vertical glowing plates, and keys 1-4 switch between clear color, depth contours, IBL caps, and particle async packets. The pointer bends attachment phase and soft-depth flow, while Space / hold injects budget pressure. Longer term, real WebGPU timestamp queries, MRT clear colors, scene-depth producer choice, IBL fallback state, and particle material build state can be packed into one telemetry texture. To viewers it reads as abstract stage lighting, while underneath it reflects actual rendering state.

制作に使えそうな技術メモProduction notes

three.js #34250 は `MRTNode.setClearColor()` で attachment ごとに clear 色を定義し、未指定時は既存の default clear policy に戻る。ID buffer は黒、normal/velocity は中立値、effect mask は明示色、といった制作時の可視化に使える。PlayCanvas #9174 は postprocess だけが depth を消費する場合に scene pass 由来の depth producer を選び、材料や shading 中 SSAO が早い段階で depth を必要とする場合は prepass を残す。#9175 の GSplat depth は単一 hard depth ではなく transmittance weighted depth なので、raymarched fog や DOF と相性がよい。Babylon #18804 の caps 修正は `colorBufferFloat`、`blendFloat`、`texelFetch`、depth/stencil metadata など、fallback 判定の入力が正しくなる点が重要。#18802 は particle node material の async build 完了を待つ修正で、空 shader fallback を防ぐ。

three.js #34250 uses `MRTNode.setClearColor()` to define clear colors per attachment, falling back to the existing default clear policy when unspecified. This is useful for production visualization such as black ID buffers, neutral normal/velocity buffers, and explicit effect-mask colors. PlayCanvas #9174 selects scene-pass depth when only post-processing consumes depth, while retaining a prepass when materials or shading-time SSAO need it earlier. #9175 writes transmittance-weighted GSplat depth rather than a single hard depth, which suits raymarched fog and DOF. Babylon #18804 matters because fallback inputs such as `colorBufferFloat`, `blendFloat`, `texelFetch`, and depth/stencil metadata become accurate. #18802 waits for particle node material async builds and prevents empty-shader fallbacks.
