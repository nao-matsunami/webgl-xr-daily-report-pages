注目事例と何が面白いかNotable examples and why they matter

今日の注目は PlayCanvas の SOG flashlight 相談と relighting docs の接続です。質問は「SOG マップに通常の SpotLight/PointLight が効かないので、画面中心だけ照らせないか」という実制作上の詰まりでした。短期なら fullscreen postprocess で暗部と円形ライトを作れる一方、影や凹凸に合わせた convincing な照明には proxy mesh を別 layer で照らし、screen-aligned texture の RGB/alpha を splat fragment に渡す relighting が必要です。Codrops の Dash Creative 事例は、video texture を shader で直接 UV 変形し、cursor の方向と減衰を JS 側で平滑化する構成が参考になります。SOG flashlight も単なる円形 mask ではなく、移動方向に少し残像/遅れを持たせると探索感が出ます。

The notable connection today is the PlayCanvas SOG flashlight forum question plus the relighting docs. The practical problem is that a SOG map does not respond to ordinary SpotLight or PointLight because it uses custom unlit splat shaders. A quick version can darken the scene and add a circular flashlight as a fullscreen postprocess, while convincing lighting and shadows need a proxy mesh on a separate layer whose screen-aligned RGB/alpha texture modulates the splat fragments. The Codrops Dash Creative case study is also relevant: it distorts a video texture directly in a fragment shader and smooths cursor direction and decay in JavaScript. A SOG flashlight should likewise avoid a static circle and carry slight motion persistence.

表現・インタラクションのアイデアExpression and interaction ideas

中心案を「SOG Flashlight PostFX Scope」に更新します。R: postprocess だけで照らしてしまう不一致、G: proxy relight coverage、B: fisheye + radial sort benefit、A: CPU sort lag / resize pressure として読みます。ポインタは一人称視点の flashlight、長押しは proxy relighting coverage を混ぜる状態、F は fisheye/radial sort、Space は resize/capture pressure です。短期では画面中心または pointer 中心の mask で十分ですが、中期では relighting.texture の alpha を coverage channel にし、currentRenderer が CPU sort のときだけ amber lag ring を出すと、表現と診断が同居します。

The central idea is updated to SOG Flashlight PostFX Scope. Read R as mismatch from a postprocess-only light, G as proxy relight coverage, B as fisheye plus radial-sort benefit, and A as CPU-sort lag / resize pressure. Pointer movement acts as a first-person flashlight, holding blends in proxy relighting coverage, F toggles fisheye/radial sort, and Space injects resize/capture pressure. A quick test only needs a screen- or pointer-centered mask. Mid term, use relighting.texture alpha as the coverage channel and show an amber lag ring only when currentRenderer is CPU sort, merging expression and diagnostics.

制作に使えそうな技術メモProduction notes

PlayCanvas v2.21.1 の MSDF 修正は、小さい注釈ラベルを splat や depth/fog 上に重ねる本プロジェクトの流れに直結します。実装時は font atlas の mipmap、coverage ramp、device pixel ratio、postprocess 後の gamma を分けて見るべきです。Babylon.js 9.18.0 の resize texture leak 修正は、canvas resize、8K capture、device pixel ratio 切替を繰り返す場合の検証項目です。PlayCanvas relighting は proxy mesh の coverage alpha を state texture として再利用できます。fisheye は radialSorting とセットで、sort artifact を UI 警告ではなく外周の blue ring / amber lag ring として可視化すると、ユーザーに『どこが危ないか』を自然に伝えられます。three.js r185 の HTMLTexture / HTML-in-Canvas 対応は、MSDF だけでは足りない注釈面の次候補です。

The PlayCanvas v2.21.1 MSDF fix directly relates to this project's repeated use of small annotation labels over splats, depth, and fog. In implementation, font-atlas mipmaps, coverage ramp, device pixel ratio, and postprocess gamma should be inspected separately. Babylon.js 9.18.0's resize texture leak fix is a verification point for repeated canvas resize, 8K capture, and device-pixel-ratio changes. PlayCanvas relighting can reuse proxy-mesh coverage alpha as a state texture. Fisheye should be paired with radialSorting, turning sort artifacts into outer blue benefit rings or amber lag rings rather than UI warnings. three.js r185's HTMLTexture / HTML-in-Canvas support remains the next annotation-plane option when MSDF alone is insufficient.

俯瞰メモBird's-eye memo

最近の傾向は、Gaussian Splat の「ファイル形式をどう読むか」から「実行時にどう光らせ、歪ませ、遅れを説明するか」へ移っています。7/17-7/23 の SOG retry / upload / export / format pressure は運用診断、7/25 の relighting / fisheye / MSDF / flashlight は鑑賞中の演出診断です。組み合わせる価値が高いのは、SOG chunk state、renderer currentRenderer、relighting coverage alpha、fisheye radialSorting、HTMLTexture/MSDF label を RGBA channel として統一することです。寝かせるのはカード UI と重い editor 全体、育てるのは「splat の見えなさ・遅れ・照明不一致を演出として見せる performance instrument」です。

The recent trend is moving from how to read Gaussian Splat formats to how to light, distort, and explain runtime lag. The 07-17 to 07-23 SOG retry / upload / export / format pressure track is operational diagnostics; the 07-25 relighting / fisheye / MSDF / flashlight track is in-view staging diagnostics. The high-value combination is to unify SOG chunk state, renderer currentRenderer, relighting coverage alpha, fisheye radialSorting, and HTMLTexture/MSDF labels as RGBA channels.
