注目事例と何が面白いかNotable example and why it matters

今日の中心事例は Cerebrium です。面白いのは、WebGPU/TSL を『未来の正解』として押し切らず、クライアント案件の初期表示時間と複数環境・複数 postprocess の compile cost を見て WebGL/GLSL へ戻している点です。さらに、戻した後も表現を単純化していません。static path mesh に UV 方向の opacity mask を走らせてネットワーク pulse を作り、Fresnel shield には procedural noise、hex grid、raycast 由来の fading mask を重ねています。これは 7/27 の Engine Parity Diff Scope と接続しやすいです。見た目差分を QA 用の赤青 heat map で終わらせず、触った場所、compile が重い場所、差分が大きい場所を『記憶する膜』として表現できます。

Today's central example is Cerebrium. The important point is that the team did not treat WebGPU/TSL as the inevitable answer; they moved back to WebGL/GLSL after judging startup time and pipeline compilation cost across multiple scenes and post-processing setups. The expression stayed rich: static path meshes are animated by moving an opacity mask along UVs, while the Fresnel shield combines procedural noise, a hex grid, and a raycast-driven fading mask. This connects cleanly to the 07-27 Engine Parity Diff Scope. Instead of ending visual differences as a red/blue QA heat map, the large-diff areas, heavy-compile areas, and touched areas can become one interaction-memory membrane.

表現・インタラクションのアイデアExpression and interaction ideas

短期案は『interaction-memory diff shield』です。画面中央に WebGPU/TSL-like と WebGL/GLSL-like の疑似差分 heat を置き、その上に Fresnel shield を重ねる。ポインタ位置は現在 hit、少し遅れた前回位置は残像 hit として扱い、押下や Space で compile / stream pressure を増やす。ユーザーが触れた場所ほど hex grid が明るくなり、差分が大きい場所ほど膜が赤く熱を持つ。中長期案は、実際の migration capture、Babylon Lite golden diff、SuperSplat export/capture queue、SOG chunk state を同じ RGBA texture にして、鑑賞者の探索行動と実装上の危険箇所が同じ表面に残る演出へ育てることです。

The short-term idea is an interaction-memory diff shield. Put a pseudo WebGPU/TSL-like versus WebGL/GLSL-like diff heat in the center, then layer a Fresnel shield over it. Current pointer position becomes the current hit; a delayed previous pointer becomes a ghost hit; hold or Space increases compile / stream pressure. Touched areas brighten the hex grid, and high-diff areas heat the membrane red. Mid/long term, feed real migration captures, Babylon Lite golden diffs, SuperSplat export/capture queues, and SOG chunk state into one RGBA texture so audience exploration and implementation risk persist on the same surface.

制作に使えそうな技術メモProduction notes

実装メモ。1. WebGPU/TSL と WebGL/GLSL の比較では、最終画像だけでなく startup / shader compile / pipeline cache の待ち時間も可視化対象にする。2. `onBeforeCompile()` 型の GLSL injection は、artist-facing material を保ちながら差分や pulse を足す移行手段になる。3. floating-point texture ping-pong は、particle simulation だけでなく pointer memory、diff accumulation、stream retry heat にも使える。4. Cerebrium の shield のように raycaster 結果を texture mask に落とすと、DOM UI ではなく shader 側に『触れた記憶』を持たせられる。5. Babylon Lite / Instancer の stable ID と slot 分離は、Gaussian splat selection や repeated object picking にも応用でき、GPU-friendly buffer と product-friendly identity の境界を明確にする設計として使えます。

Production notes: 1. When comparing WebGPU/TSL and WebGL/GLSL, visualize not only final-image differences but also startup, shader compilation, and pipeline-cache waiting. 2. `onBeforeCompile()`-style GLSL injection is a useful migration tactic for adding diffs or pulses while keeping artist-facing materials intact. 3. Floating-point texture ping-pong works not only for particle simulation but also for pointer memory, diff accumulation, and stream-retry heat. 4. Converting raycaster output into a texture mask, as in Cerebrium's shield, lets the shader layer own interaction memory instead of DOM UI. 5. Babylon Lite / Instancer's split between stable IDs and render slots is applicable to Gaussian-splat selection and repeated-object picking, clarifying the boundary between GPU-friendly buffers and product-friendly identity.
