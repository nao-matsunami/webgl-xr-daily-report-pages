1. three.js PR #34402 は VXGINode、つまり Voxel Cone Tracing による diffuse GI を提案している。PR本文では SSGI と Light Probe Grid の中間に位置づけられ、screen-space artifact を避けながら動的ライトを扱う方向が示されている。2. three.js PR #34235 の PrefixSum は引き続き更新され、前回の compute lifecycle から「sort や scan の状態そのものを見せる」線が強い。3. PlayCanvas PR #9233 は streamed SOG / GSplat の LOD 選択を距離ではなく `coverage * error removed / splats added` で買う方式に変える。表現上は、視点距離よりも「失われる細部」を演出値にできる。4. Babylon.js PR #18822 の MultiTexture は RawTexture2DArray を使った shader-level 合成で、add/remove/insert/update できる layer が表現の時間軸になる。5. Babylon.js WebGPU-XR Phase 5 issue は capability detection、fallback、in-headset manual validation を明文化しており、XR の表現サンプルでも「対応していない状態」を演出に含める価値がある。

1. three.js PR #34402 proposes VXGINode, a diffuse-GI node based on Voxel Cone Tracing. The PR positions it between SSGI and Light Probe Grid: fewer screen-space artifacts than SSGI, while supporting dynamic lighting more directly than baked probes. 2. three.js PR #34235 continues PrefixSum work, reinforcing yesterday's compute-lifecycle direction of making scan and sort state visible. 3. PlayCanvas PR #9233 changes streamed SOG / GSplat LOD selection from distance bands to buying upgrades by `coverage * error removed / splats added`; visually, quality loss can become a stronger expressive signal than camera distance. 4. Babylon.js PR #18822 MultiTexture uses RawTexture2DArray for shader-level layer composition with add/remove/insert/update operations. 5. Babylon.js WebGPU-XR Phase 5 explicitly calls out capability detection, fallback, and manual in-headset validation, making unsupported state part of the XR design surface.

表現・インタラクションのアイデアExpression and interaction ideas

本命案は「VXGI Error LOD Cone Field」。ドラッグ位置を光源と誤差の焦点にして、cone tracing 風の扇、voxel予算grid、error-driven splat LODを切り替える。クリック/Spaceで予算pulseを入れると、細部を買う領域が広がる。派生案は「Multiview Layer Resolve Scope」。Babylon.js MultiTexture、white balance、WebXR composition layer、three.js WebXR single-pass resolveの話題を、左右の目に分かれたlayer stackとして描く。pointerで eye offset と layer order を変え、完成したlayerだけwhite balance lensで戻す。次に足すなら、1本目の error score を2本目の per-eye layer opacity に渡し、高誤差領域だけ片目側の解像度やlayer数を増やす。

The main idea is VXGI Error LOD Cone Field. Dragging sets both the light source and error focus, switching between cone-tracing fans, voxel-budget grids, and error-driven splat LOD. Click/Space sends a budget pulse that expands where detail is bought. The derived idea is Multiview Layer Resolve Scope, turning Babylon.js MultiTexture, white balance, WebXR composition layers, and three.js WebXR single-pass resolve into a left/right-eye layer stack. The pointer controls eye offset and layer ordering, while a white-balance lens corrects only completed layers. Next, send the first sample's error score into the second sample's per-eye layer opacity so high-error regions receive more layer or resolution budget.

制作に使えそうな技術メモProduction notes

VXGIを作品に使う場合、voxel resolution、cone count、voxelization update interval、light leak量をUI値ではなく色温度、残光、粒子密度に割り当てると観客に内部コストが伝わる。GSplat LODは距離ベースから error-driven に変えると、近距離でも平坦な領域は粗く、遠距離でも細部が重要な領域は残せる。これは XR や展示で視線、手、音量をcoverageに混ぜると強い。MultiTextureは RawTexture2DArray 前提なので WebGL2+ の境界を明示する必要があるが、layer add/remove/update がそのまま拍やカット編集になる。WebGPU-XR の fallback は、単に警告表示するより、unsupported path を低解像layer、モノクロpass、遅延resolveとして見せるほうがこのプロジェクトには合う。実装時の図形は短辺基準座標で正円・正方形を保ち、歪みはeye offsetやlens効果の理由がある場所だけに限定する。

For VXGI-based work, map voxel resolution, cone count, voxelization update interval, and light leaking to color temperature, afterglow, and particle density instead of plain UI values. With error-driven GSplat LOD, flat regions can stay coarse even nearby, while detail-rich areas can remain higher quality at distance; this becomes stronger in XR or installations when gaze, hands, or volume feed into coverage. MultiTexture depends on RawTexture2DArray and therefore WebGL2+, but layer add/remove/update operations naturally become beats and edits. For WebGPU-XR fallback, show unsupported paths as low-resolution layers, monochrome passes, or delayed resolve rather than plain warning text. Keep base geometry on short-edge-normalized coordinates so circles and squares remain clean; reserve distortion for eye offset and lens effects with a visible reason.
