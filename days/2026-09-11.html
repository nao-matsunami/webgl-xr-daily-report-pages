注目事例と何が面白いかNotable examples and why they matter

Infinite Loom の面白さは、見た目は画像スライダーでも、実体は ribbon geometry / random seed / edge tear / fragment alpha の組み合わせになっている点。共有頂点のある1枚板を細分化すると膜のように伸びるが、独立リボンにすると隙間が開き、時間差が形になる。これは SOG / point cloud / object ID buffer と近い。「1枚の絵」ではなく、「多数の素片が同じ絵に見えているだけ」と考えると、LOD低下、stream遅延、片目resolve、readback詰まりを作品の破綻ではなく、ほどける演出として扱える。Liquid Glass も同じく、本物の厚みではなく shader 内の距離場と屈折で質感を作る。最近の流れは、WebGL/WebGPU の最適化や診断値を、隠すのではなく素材化する方向に寄っている。

Infinite Loom is interesting because it looks like an image slider, but it is really ribbon geometry, random seeds, edge tearing, and fragment alpha. A subdivided single plane with shared vertices stretches like a membrane; independent ribbons create gaps and make time offsets visible. This is close to SOG, point clouds, and object ID buffers. If an image is not one image but many fragments temporarily agreeing to look like one, LOD reduction, stream delay, per-eye resolve, and readback congestion can become unraveling effects rather than failures. Liquid Glass similarly uses shader distance fields and refraction instead of real thickness. The recent trend is to materialize optimization and diagnostic values instead of hiding them.

制作に使えそうな技術メモProduction notes

リボン分割は、1枚の plane を細分化するより、strip ごとに独立した頂点列を持たせる方が破れ・隙間・アルファ制御を作りやすい。shader 側では threadId / stripIndex を seed にして drift、flutter、fade、whiten を変える。SOG LOD と接続するなら、空 coarse level、distance error、fallback LOD、streamed detail falloff を RGBA state texture にして、R=stability、G=loaded detail、B=distance error、A=age のように割り当てると扱いやすい。XR では single-pass / multiview / attachment resolve の差分を、左右目のリボンずれや scanline density として出すと、技術差が見える演出になる。Babylon.js 側の object ID geometry textures は、pick / selection / segmentation を postprocess へ渡すだけでなく、色分解、輪郭、異常検知、stream diagnostics の素材として使える。

For ribbon splitting, independent vertex strips are more controllable than subdividing a single plane, because tearing, gaps, and alpha can be controlled per strip. In the shader, use threadId / stripIndex as seeds for drift, flutter, fade, and whitening. To connect with SOG LOD, pack empty coarse level, distance error, fallback LOD, and streamed detail falloff into an RGBA state texture: R=stability, G=loaded detail, B=distance error, A=age. In XR, single-pass, multiview, and attachment resolve differences can appear as per-eye ribbon offsets or scanline density. Babylon.js object ID geometry textures can drive not only picking and segmentation but also color splitting, outlines, anomaly detection, and stream diagnostics.

サンプルデータの可能性と組み合わせ考察Possibilities for the sample data and combinations

今日の2本は、render state をログ化するとかなり育てやすい。1本目は pointer、tear focus、ribbon id、LOD stability、empty coarse flag、pulse、mode を保存できる。音反応なら低域を ribbon drift、中域を LOD回復、高域を白抜けやRGBずれへ割り当てるとライブ向き。WebXR では左右目の resolve / multiview 状態を ribbon の位相差にできる。2本目は object id、USD chunk progress、stream diagnostic row、pool hit/miss、selection heat を保存できる。MediaPipe やカメラ入力を使うなら、手や顔の領域だけ ID plate を熱くし、背景はUSD chunkとして遅れて追従させると、実写と診断情報が同じ画面で混ざる。展示・VJ・プロダクト演出では「状態が乱れるほど画がほどけ、回復すると織り直される」という分かりやすい演出軸になる。

Both samples become more useful if render state is logged. The first can save pointer, tear focus, ribbon id, LOD stability, empty coarse flag, pulse, and mode. For audio response, map low bands to ribbon drift, mids to LOD recovery, and highs to whitening or RGB offset. In WebXR, per-eye resolve / multiview state can become ribbon phase difference. The second can save object id, USD chunk progress, stream diagnostic row, pool hit/miss, and selection heat. With MediaPipe or camera input, heat only the hand or face region in the ID plate while the background follows as delayed USD chunks, mixing live video and diagnostics. For installations, VJ, and product experiences, the clear motif is: the image unravels as state becomes unstable, then weaves itself back together as it recovers.
