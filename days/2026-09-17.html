注目事例と何が面白いかNotable examples and why they matter

今日の中心はSuperSplat 3.0。重いGaussian sceneを軽く見せるだけでなく、編集、選択、histogram、exportの途中状態までGPU compute側へ移している点が重要。特にStochastic Alphaは、動いている間だけsort負荷を下げ、止まったら正確なsorted frameへ戻すという時間設計そのものが演出に使える。Sphere Brushは、depth-picked pathとsurface footprintを持つので、9/16のprobe / culling案と接続しやすい。Babylon 9.26.2のmesh blending post processとKHR_interactivityは、見た目のblendだけでなく、状態遷移、trigger、procedural uniform updateを1つのshader面へ載せる材料になる。

The key case today is SuperSplat 3.0. It is not just making heavy Gaussian scenes lighter; it moves editing, selection, histograms, and export-in-progress state toward GPU compute. Stochastic Alpha is especially useful because it intentionally lowers sorting cost while moving and returns to a precise sorted frame when still, making the time design itself expressive. Sphere Brush has a depth-picked path and surface footprint, so it connects cleanly to September 16's probe / culling track. Babylon 9.26.2's mesh blending post process and KHR_interactivity are not just visual blending; they provide material for mapping state transitions, triggers, and procedural uniform updates onto one shader surface.

表現・インタラクションのアイデアExpression and interaction ideas

本命案は「Stochastic Brush Memory Scope」。重いsplat sceneのediting中だけ画が粗くなるのを隠さず、stochastic coverage、brush footprint、selection color grade、export chunkを可視化する。dragでbrush path、clickでselection pulseを出し、止まるとsorted/rest frameへ寄るような体験にする。派生案は「Mesh Blend Interactivity Stage」。mesh blending post processを、単なるfadeではなく、KHR_interactivityのtrigger graph、ProceduralTexture uniform setter、Inspector text/sprite layerの状態表示と混ぜる。イベントが来るたびにmeshの境界、node graph、uniform laneが同じpulseで変わる。

The main idea is Stochastic Brush Memory Scope: do not hide the rougher image during heavy splat editing; instead visualize stochastic coverage, brush footprints, selection color grades, and export chunks. Drag creates a brush path, click emits a selection pulse, and the scene should drift back toward a sorted / rest frame when still. The derived idea is Mesh Blend Interactivity Stage: treat mesh blending post process not as a simple fade but as a blend of KHR_interactivity trigger graphs, ProceduralTexture uniform setters, and Inspector text / sprite layer state. Each event changes mesh boundaries, node graphs, and uniform lanes with the same pulse.

制作に使えそうな技術メモProduction notes

Stochastic Alpha系は、renderMode、cameraMoving、sortedFrameMs、stochasticEnabled、coverageSeed、gaussianCount、selectedCount、brushRadius、footprintMode、depthPickValidを小さなstate schemaにすると試しやすい。Sphere Brushのpathは点列として持ち、各点にworld position、depth discontinuity、radius、operation(add/remove/intersect)を付けると、後から同じstrokeをreplayできる。mesh blending / KHR_interactivityは、triggerId、stateBefore、stateAfter、transitionWeight、proceduralUniformName、uniformType、uniformValue、postProcessMixをRGBA laneへ詰める。9/16のHTMLTexture/TAA inspectorと組み合わせるなら、UI snapshotのdirty rectとselection dirty regionを同じtexture atlasに入れる。

For Stochastic Alpha work, start with a small state schema: renderMode, cameraMoving, sortedFrameMs, stochasticEnabled, coverageSeed, gaussianCount, selectedCount, brushRadius, footprintMode, and depthPickValid. Store Sphere Brush paths as point lists, with world position, depth discontinuity, radius, and operation (add / remove / intersect) on each point, so strokes can be replayed later. For mesh blending / KHR_interactivity, pack triggerId, stateBefore, stateAfter, transitionWeight, proceduralUniformName, uniformType, uniformValue, and postProcessMix into RGBA lanes. When combining with September 16's HTMLTexture / TAA Inspector work, place UI snapshot dirty rectangles and selection dirty regions into one texture atlas.
