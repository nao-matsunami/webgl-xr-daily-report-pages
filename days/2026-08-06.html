制作に使えそうな技術メモProduction notes

KHR_interactivity 系は、ref をただの文字列として扱わず、JSON Pointer 風の安定 ID としてログ・可視化・テストに流すとよい。event cancellation は見えない分岐なので、停止地点を shader uniform や debug texture に出すと制作時の理解が速い。WebGPU-XR では Raw Camera Access のように runtime capability で意図的に無効化される機能を、generic error ではなく feature-specific warning と guard channel に分ける。three.js DirectRenderPipeline のような直通経路では、framebuffer sampling を前提にした postprocess は成立しない場合があるため、素材側 shader へ寄せるか、別 capture pass を明示する。PlayCanvas の per-attachment clear は、color/id/depth-risk/event-state のような複数レーンを同じ画面で検査する基盤になる。

For KHR_interactivity, treat refs not as plain strings but as stable JSON Pointer-like IDs that can flow into logs, visualization, and tests. Event cancellation is an invisible branch, so exposing the stop point as a shader uniform or debug texture speeds up production understanding. In WebGPU-XR, intentionally disabled runtime capabilities such as Raw Camera Access should split into feature-specific warnings and guard channels instead of generic errors. With a direct path like three.js DirectRenderPipeline, postprocess relying on framebuffer sampling may no longer fit, so move expression into material shaders or make a separate capture pass explicit. PlayCanvas per-attachment clear provides the basis for inspecting multiple lanes such as color, id, depth risk, and event state on one screen.

俯瞰メモBird's-eye memo

最近の流れは、Gaussian Splatting や XR の派手な機能追加よりも、内部状態の見える化が作品と検証の両方に効いていること。clear、attachment、ref、event、guard、readback、compiler workaround は、普段は開発者だけが見る層だが、色・線・遮断・流れに変換すると体験の文法になる。昨日の per-eye clear scope は render pass の境界、今日の interactivity ref event scope は asset/event の境界を扱う。両者を組み合わせると、入力イベントがどの attachment を clear し、どの XR feature を guard し、どの direct path に流れるかを一枚で見せる中長期テーマになる。

The recent pattern is that making internal state visible helps both expression and verification more than flashy new Gaussian Splatting or XR features alone. Clear, attachments, refs, events, guards, readback, and compiler workarounds are usually developer-only layers, but when translated into color, lines, blocks, and flows they become an interaction vocabulary. Yesterday's per-eye clear scope covered render-pass boundaries; today's interactivity ref event scope covers asset/event boundaries. Combining them suggests a mid- to long-term theme: one view showing which input event clears which attachment, guards which XR feature, and flows into which direct path.
