注目事例と何が面白いかNotable examples and why they matter

Babylon Mesh Blending が面白いのは、接触面の破綻をアセット編集ではなく screen-space の後処理で扱い、tag、depth、SceneColor、必要ならalbedoから安定した seam fade を作る点。これは 10/9 の shadow / occlusion、10/12 の refraction guard、10/13 の fallback haze と同じく、完成画の手前にある補正層を表現へ転用できる。PlayCanvas Editor 2.34 の Inspector / Splat Budget Mode は、アプリ内部の resource / frame graph / GPU state を見える面に出す方向で、これを作品側の HUD ではなく空間の粒子密度や熱として扱うと、診断と演出が重なる。Codrops の pointer lens と Volatile Nexus は、ポインタ、ガラス、音の反応で局所的に空間の物性が変わる例として参考になる。

Babylon Mesh Blending is interesting because it treats contact artifacts as a screen-space post-process rather than asset editing, producing stable seam fade from tags, depth, SceneColor, and optionally albedo. Like 10/9 shadow / occlusion, 10/12 refraction guard, and 10/13 fallback haze, it turns the correction layer before the final image into expressive material. PlayCanvas Editor 2.34's Inspector / Splat Budget Mode surfaces resource, frame graph, and GPU state; if those values drive spatial particle density or heat instead of a separate HUD, diagnostics and performance become part of the scene. Codrops pointer lens and Volatile Nexus are useful references for pointer-local changes in materiality through glass, sound, and distortion.

制作に使えそうな技術メモProduction notes

Mesh Blending 系の実装で取るべきログは `meshBlendTag/groupId/radiusClass/depthType/searchRadius/slopeFactor/quality/debugMode/attenuation/baseColorAvailable/rejectedContactCount`。PlayCanvas / splat budget 系は `splatBudget/lodLevel/coarseFirstRank/appStatsGpuMs/appStatsDrawCalls/resourceTextures/resourceBuffers/resourcePipelines/inspectorStep/passId/canvasResolutionKept/miniStatsSkipped`。three.js r187 系は `pipelineCompileMs/nodeIntentId/fp16Path/webglFallbackLoaded/rangeStart/rangeEnd/refractionGuardDepth/blurTapCount`。これらを 32x8 か 64x8 の state texture に詰め、横を時間、縦を subsystem にする。描画では seam fade、budget ring、heat lane、glass lens の4表現に分けると、後から実エンジンのログに差し替えやすい。

For Mesh Blending-style work, useful log fields are `meshBlendTag/groupId/radiusClass/depthType/searchRadius/slopeFactor/quality/debugMode/attenuation/baseColorAvailable/rejectedContactCount`. For PlayCanvas / splat budget, track `splatBudget/lodLevel/coarseFirstRank/appStatsGpuMs/appStatsDrawCalls/resourceTextures/resourceBuffers/resourcePipelines/inspectorStep/passId/canvasResolutionKept/miniStatsSkipped`. For three.js r187, track `pipelineCompileMs/nodeIntentId/fp16Path/webglFallbackLoaded/rangeStart/rangeEnd/refractionGuardDepth/blurTapCount`. Pack these into a 32x8 or 64x8 state texture with time on the horizontal axis and subsystem on the vertical axis. Separating the rendering into seam fade, budget rings, heat lanes, and glass lens makes it easy to replace the synthetic values with real engine logs later.

俯瞰メモBird's-eye memo

最近の流れは、renderer の弱点や補正層がそのまま表現素材になっていること。10/9 の shadow / occlusion、10/12 の Range / recovery、10/13 の backpressure / glitch、今日の seam / inspector / budget は一本の render-state score に載せられる。組み合わせると面白いのは、Mesh Blending の tag と radius class を点群や音の粒度へつなぎ、PlayCanvas の AppStats を密度や熱に、three.js の fallback / Range を読み込みの拍に、Codrops の lens / glass を局所的な物性変化にする構成。育てる価値が高いテーマは、隠されがちな「接触、待ち、負荷、回復」を、作品の触れる質感として表に出す方向。

The recent pattern is that renderer weaknesses and correction layers are becoming visual material. 10/9 shadow / occlusion, 10/12 Range / recovery, 10/13 backpressure / glitch, and today's seam / inspector / budget can live on one render-state score. A strong combination maps Mesh Blending tags and radius classes to splat or audio granularity, PlayCanvas AppStats to density and heat, three.js fallback / Range to loading beats, and Codrops lens / glass ideas to local material changes. The high-value direction is to expose contact, waiting, load, and recovery as tactile qualities of the work.
