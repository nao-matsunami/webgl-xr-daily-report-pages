PlayCanvas Engine v2.23.0が10/1に出ており、WebGPUでmesh instance matricesをpersistent storage bufferへ置く、partial vertex/index buffer upload、view uniform bufferへのper-pass uniform移動、view bind group経由のper-pass texture供給、pipeline再利用、material bind group、Gaussian Splatting LOD / stochastic alphaなど、描画状態の粒度を細かく保つ変更が多い。2. Babylon.js 9.29.0も10/1に出ており、frame graph min/max reducer、velocity outputのprevious world matrix追跡、CPU particlesのper-frame allocation削減、cached texture retry、WebGPU 3D texture mipmap修正が目立つ。3. three.js r187 migrationはPMREM cube render target、WeakRef / FinalizationRegistry、XR camera matrix、bound render target時のviewport/scissor、pixelationPass Number化を引き続き確認対象にする。4. 1. PlayCanvas Engine v2.23.0 was released on Oct 1 and includes many changes that keep render state granular: persistent storage buffers for mesh instance matrices on WebGPU, partial vertex/index buffer uploads, per-pass uniforms moved into the view uniform buffer, per-pass textures supplied through the view bind group, render pipeline reuse, material bind groups, and Gaussian Splatting LOD/stochastic alpha work. 2. Babylon.js 9.29.0 also landed on Oct 1, with a frame-graph min/max reducer, previous world-matrix tracking for velocity outputs, fewer per-frame CPU-particle allocations, cached texture retries, and a WebGPU 3D texture mipmap fix. 3. The three.js r187 migration remains important for PMREM cube render targets, WeakRef/FinalizationRegistry, XR camera matrices, viewport/scissor with bound render targets, and pixelationPass Number inputs. 4. Codrops examples such as Wide grid, custom-shaped cursor trail, and Paper Crumple remain useful as references for turning input and deformation into needles that read shader state.

注目事例と何が面白いかNotable examples and why they matter

PlayCanvas v2.23.0は、単にWebGPU対応を進めるというより、view / material / mesh / light / splatの状態境界を整理している点が面白い。これを視覚化すると、従来の派手なポストエフェクトではなく「いつ、どの単位でGPUに渡ったか」が作品のリズムになる。Babylon 9.29.0のframe graph min/max reducerとvelocity修正は、画面上の値の範囲と前フレームの記憶を同じ演出素材にできる。three.js r187のviewport/scissorやPMREM変更は、10/1の診断面を継続して実フレームログへ近づける接続点になる。

PlayCanvas v2.23.0 is interesting because it is not only about WebGPU support; it clarifies state boundaries across view, material, mesh, light, and splat paths. Visualized creatively, the rhythm becomes when and at what granularity data reaches the GPU, rather than a flashy post effect. Babylon 9.29.0's frame-graph min/max reducer and velocity fixes make value ranges and previous-frame memory usable as one material. three.js r187's viewport/scissor and PMREM changes keep yesterday's diagnostic surfaces connected to real frame logs.

Short term: turn the view uniform buffer, material bind groups, and partial upload ranges into a four-quadrant shader score, with drag controlling the camera/view probe and clicks emitting upload pulses. Derived idea: make Babylon's frame-graph reducer, velocity history, and cached texture retries into horizontal lanes where recovery and failure become visible events. Longer term: merge this with 10/1's viewport/scissor/PMREM, 9/29's residency, and 9/30's layer/depth work as one render-state atlas.

制作に使えそうな技術メモProduction notes

PlayCanvas v2.23.0を見ると、WebGPUではper-pass uniform、texture、material、mesh override、light slot、pipeline cacheの持ち方が実装品質に直結する。ログ化するなら `viewId/passId/bindGroupId/materialId/partialUploadOffset/partialUploadBytes/pipelineCacheHit/splatLodLevel/stochasticAlpha` を候補にする。Babylon 9.29.0側は `frameGraphBlock/minValue/maxValue/previousWorldMatrixValid/velocityMagnitude/textureRetryCount/cacheHit/mipmapLevel` が良い。three.js側は `viewportScale/scissorRect/pmremFace/textureAge/finalizedAtFrame/pixelSize` を継続して採る。

PlayCanvas v2.23.0 suggests that WebGPU implementation quality depends heavily on how per-pass uniforms, textures, materials, mesh overrides, light slots, and pipeline caches are owned. Candidate log fields are `viewId/passId/bindGroupId/materialId/partialUploadOffset/partialUploadBytes/pipelineCacheHit/splatLodLevel/stochasticAlpha`. For Babylon 9.29.0, useful fields include `frameGraphBlock/minValue/maxValue/previousWorldMatrixValid/velocityMagnitude/textureRetryCount/cacheHit/mipmapLevel`. For three.js, continue collecting `viewportScale/scissorRect/pmremFace/textureAge/finalizedAtFrame/pixelSize`.

The recent trend is moving away from one large GPU picture and toward showing update granularity, ownership granularity, lifetime, and recovery from failure. 9/29's residency, 9/30's layer/depth, 10/1's viewport/scissor, and 10/2's bind-group/frame-graph work all connect as attempts to make render-state granularity into art.
