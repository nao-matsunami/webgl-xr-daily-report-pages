制作に使えそうな技術メモProduction notes

`updateBefore` / `updateAfter` を compute に入れる場合、準備passが textureStore 対象や blur input を更新する順序をログに残すと、黒画面や1フレーム遅延の原因を追いやすい。PrefixSum は binCount を増やすほどメモリコストが増えるため、作品化するなら `binCount`, `prefixMs`, `visibleSplatCount`, `fallbackSingleThread` をHUDではなく発光/粒子密度/scan速度に割り当てるとよい。NPOT mipmap は WebGL2 では生成できるが、mipmap upload と gpuSize が揃って初めて品質と予算が同じ言語になる。procedural geometry tangent は Box/Circle/Sphere/Plane/Torus/Capsule/Cone/Cylinder で同じ基底処理に寄せられるため、サンプル素材では tangent方向を色や縞で出すと品質差が分かりやすい。CSP対応の Inspector は、公開ギャラリーや商用サイトで診断UIを安全に埋める前提としてウォッチする価値がある。

When `updateBefore` / `updateAfter` enter compute execution, log the order in which preparation passes update textureStore targets or blur inputs; it helps diagnose black frames and one-frame-late artifacts. PrefixSum increases memory cost as binCount rises, so expressive prototypes should map `binCount`, `prefixMs`, `visibleSplatCount`, and `fallbackSingleThread` to glow, density, or scan speed rather than plain HUD text. NPOT mipmaps are valid in WebGL2, but mipmap upload and gpuSize accounting must match before quality and budget use the same language. Procedural-geometry tangent generation moving to a common base method makes tangent direction worth showing with color and stripes across Box/Circle/Sphere/Plane/Torus/Capsule/Cone/Cylinder assets. Inspector CSP support is worth watching for safely embedding diagnostic UI in public galleries or commercial sites.
