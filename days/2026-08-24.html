The strongest signal today is Tour of TSL advancing alongside GPU unit tests. With learning docs, playground, runner, and real GPU validation, a loop emerges: read a shader helper, try it, break it, and visualize the difference. Adding Babylon MultiTexture prevents pass/fail from staying monochrome: results can become layers, blend modes, and replacement history. Combining PlayCanvas #9167 then allows per-sample decisions inside one pixel. This becomes not a screen of test results, but a surface where tests are performed.

制作に使えそうな技術メモProduction notes

TSL/WGSLでは select や if で未到達に見える式でも、compile-time constant folding が先に走ると division by zero などで shader module 作成時に落ちる。#34350 の depth/bit/BRDF検証は、見た目のテストでは拾えない backend差分を明示する材料になる。PlayCanvas #9167 の `bindMultisampled` は、MSAA color attachment を保存し、`texture_multisampled_2d` として user shader から sampleIndex 付きで読む設計。Babylon #18822 の MultiTexture は WebGL2+ 前提の RawTexture2DArray なので、WebGL1サンプルでは疑似layerに留めたが、実装時は layerの寸法統一、dispose race、watch polling、tree-shaking side effects を見る必要がある。#18820 の offscreen suspension は、render loop停止とscene registrationを分ける点が重要で、画面外復帰時のdelta spikeを避ける実装メモとして使える。

In TSL/WGSL, expressions that look unreachable behind select or if can still be constant-folded first; division by zero can fail shader-module creation. #34350's depth/bit/BRDF validation is useful because it exposes backend differences that visual tests miss. PlayCanvas #9167's `bindMultisampled` stores the MSAA color attachment and exposes it as `texture_multisampled_2d` for sampleIndex-based user shader reads. Babylon #18822's MultiTexture is WebGL2+ RawTexture2DArray, so today's WebGL1 sample only simulates layers; real use should check layer dimension normalization, disposal races, watch polling, and tree-shaking side effects. #18820's key implementation note is separating render-loop state from scene registration so resume avoids delta spikes.

俯瞰メモBird's-eye memo

最近の傾向はかなり明確で、WebGL/WebGPUの表現は「きれいなshader」から「renderer内部の判断を観客が触れる状態面」へ寄っている。fog/JBU、branch cache、sampler audit、alphaToCoverage、MSAA sample、offscreen suspension、MultiTexture、TSL unit test は別々の話に見えるが、全部、どの値を信用し、どの層を描き、どの予算を使うかの可視化でつながる。組み合わせ候補は、TSL test failure を MultiTexture layer にして、MSAA sampleごとに違う failure色をresolveすること。育てる価値が高いテーマは「shader playground がそのまま舞台になる」こと。Tour of TSL は、その足場になり得る。

The recent trend is clear: WebGL/WebGPU expression is moving from beautiful shaders toward state surfaces where viewers can touch renderer decisions. Fog/JBU, branch caching, sampler audits, alphaToCoverage, MSAA samples, offscreen suspension, MultiTexture, and TSL unit tests look separate, but all visualize which values are trusted, which layers are drawn, and which budget is spent. A strong combination is to turn TSL test failures into MultiTexture layers and resolve different failure colors per MSAA sample. The theme worth growing is the shader playground becoming the stage itself. Tour of TSL could be the scaffold.

サンプルデータの可能性と組み合わせ考察Possibilities for the sample data and combinations

今日の2サンプルは、入力値、検証カテゴリ、layer番号、blend mode、pulse時刻をデータとして取り出せる。展示なら、来場者のpointerや音量で test category がlayerとして増減し、失敗したbackendだけ異なる色で発光する壁面にできる。Webサイトなら、scrollで offscreen budget とlayer更新を同期し、見えていない3D要素は止まり、戻ると履歴が地層として残る。WebXRなら、左右眼やsampleIndexごとに違う検証layerを見せ、正しさの差を立体視の違和感として扱える。MediaPipeやカメラを足す場合は、手の距離を expected-value lens、指の本数を bit-count lane、顔の向きを Euler/depth roundtrip に割り当てると、QAの言葉を身体的な演奏に変えられる。

The two samples expose inputs, validation categories, layer IDs, blend modes, and pulse timing as data. In an installation, visitor pointer or audio amplitude could add and remove test categories as layers, with failing backends glowing in distinct colors. On a website, scroll could synchronize offscreen budget and layer updates: hidden 3D elements stop, and when they return their history remains as strata. In WebXR, each eye or sampleIndex could show different validation layers, making correctness differences into stereoscopic tension. With MediaPipe or camera input, hand distance can drive the expected-value lens, finger count can select bit-count lanes, and face direction can control Euler/depth roundtrip, turning QA vocabulary into bodily performance.
