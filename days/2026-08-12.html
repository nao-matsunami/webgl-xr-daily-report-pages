注目事例と何が面白いかNotable examples and why they matter

最も面白いのは three.js #34215。Gaussian Splat は点群的な密度表現として見られがちだが、SH が入ると「位置と色の集合」から「見る角度で性格が変わる素材」へ寄る。PR では Lion の回転時に白い fringe が正しく見えること、SH degree ごとの bytes per splat、WebGPU pre-pass と WebGL fallback の違いまで書かれている。これは昨日の error budget に接続しやすい。高 error node を単に明るくするのではなく、視線に対して sheen が立つ node を優先し、鑑賞者が動くほど品質配分が変わる演出にできる。

The strongest example is three.js #34215. Gaussian Splats are often read as point-density representation, but with SH they become materials whose character changes with view angle. The PR documents the Lion's white fringe during rotation, bytes per splat by SH degree, and the WebGPU pre-pass versus WebGL fallback split. This connects directly to yesterday's error budget: instead of simply brightening high-error nodes, prioritize nodes whose sheen responds to the viewer, so quality allocation changes as the audience moves.

表現・インタラクションのアイデアExpression and interaction ideas

短期案は「View Sheen Budget Scope」。疑似 splat 群に view vector を与え、pointer drag で視点方向を変える。spherical harmonics 風の係数は本物ではなく、簡易 dot / pow で白い sheen と色相変化を出す。mode 2 では Babylon #18797 の light clamp を 13 個の light lane と 9 本目の budget line で表示し、Hold / Space で超過分を赤く落とす。mode 3 は three.js #34212/#34211 の BatchedMesh offset mismatch を WebGPU / WebGL parity lane として、mode 4 は Babylon #18798 の texture identity collision を embedded texture panel として描く。中長期では実 SH degree、実 maxUniformBuffersPerShaderStage、実 GLB cache key を同じ診断テクスチャに流す。

The short-term idea is View Sheen Budget Scope. Give a pseudo-splat cluster a view vector and let pointer dragging change view direction. Instead of real spherical harmonics, use simple dot / pow terms to create white sheen and hue shifts. Mode 2 visualizes Babylon #18797 as 13 light lanes and a ninth-light budget line, dropping overflow lights in red when holding or pressing Space. Mode 3 turns three.js #34212/#34211 into WebGPU/WebGL parity lanes for BatchedMesh offset mismatch. Mode 4 renders Babylon #18798 as embedded texture panels with identity collisions. Longer term, feed real SH degree, real maxUniformBuffersPerShaderStage, and real GLB cache keys into one diagnostic texture.

制作に使えそうな技術メモProduction notes

SH splat は、見た目の豊かさだけでなく loader / memory / backend 分岐の設計にも関わる。PR #34215 では SH degree が上がるほど bytes per splat が増え、WebGPU pre-pass では ellipsoid 全体で一定の view dependency を先に計算し、WebGL fallback では vertex shader で複数回計算する。つまり、表現側では「艶が出る」だが、実装側では「どこで一回だけ計算できるか」が重要。Babylon #18797 は light count を artist-facing な slider にする場合、WebGPU caps を越えた瞬間に黒画面化させず、警告・clamp・可視化する必要を示す。#18798 は data URL / file URL のような名前を持たない素材でも、キャッシュキーに一意性を持たせることが texture mix-up 防止に直結する。three.js #34212 は byte offset と element offset の単位を記録する重要性を示している。

SH splats affect not only visual richness but also loader, memory, and backend design. In PR #34215, bytes per splat increase with SH degree; the WebGPU path precomputes view dependency once per ellipsoid, while the WebGL fallback repeats the work in the vertex shader. Visually this means sheen, but implementation-wise the question is where a value can be computed once. Babylon #18797 shows that artist-facing light-count sliders need WebGPU-cap awareness, warning, clamping, and visualization rather than black frames. #18798 shows that even nameless data/file sources need unique cache keys to prevent texture mix-ups. three.js #34212 highlights the need to preserve byte-versus-element offset units.
