注目事例と何が面白いかNotable examples and why they matter

最も面白い事例は Grace Cathedral Experience です。外観と内観を別 splat set として扱い、streamed SOG の粗い LOD から time-to-first-pixel を作り、desktop と mobile で splat budget を分け、mode switch は freeze-fade で隠します。さらに cutout は gsplat shader chunk で per-splat stage と fragment stage に分け、壁を覗く演出と culling を同じ構造で成立させています。これは 7/26 の format pressure scope と直結します。format や renderer の違いをユーザーから隠すだけでなく、差分が大きい場所を glowing rim、freeze residue、stream heat として見せると、検証ツールと演出が同じレイヤーになります。

The most interesting case is the Grace Cathedral Experience. It treats exterior and interior as separate splat sets, starts with coarse streamed-SOG LOD for time-to-first-pixel, splits splat budgets between desktop and mobile, and hides mode switches with a freeze-fade. Its cutout effect uses gsplat shader chunks split between per-splat and fragment stages, making both wall-peeking expression and culling share the same structure. This connects directly to the 07-26 format-pressure scope. Instead of only hiding format or renderer differences, show high-difference areas as glowing rims, freeze residues, and stream heat so the same layer works as both verification tool and visual direction.

表現・インタラクションのアイデアExpression and interaction ideas

今日の中心案は「parity diff を触れる照明にする」です。左右に legacy/WebGL-like path と V2/Lite-like path を置き、中央に pixel diff heat を出す。ポインタを inspection lens、長押しや Space を migration stress とし、color space、post FX、MSDF label、streamed splat budget の差分だけが強く光るようにします。短期では疑似 shader で十分です。中長期では PlayCanvas の Engine V2 migration 前後スクリーンショット、Babylon Lite と Babylon.js の golden image、SuperSplat export 前後を texture として読み、差分を bloom rim、粒子密度、音の帯域へ流し込むと、QA と作品性が接続できます。

Today's core idea is to make parity diffs into touchable lighting. Put a legacy/WebGL-like path on the left, a V2/Lite-like path on the right, and emit pixel-diff heat in the center. Pointer becomes an inspection lens; hold or Space becomes migration stress; only the differences in color space, post FX, MSDF labels, and streamed splat budgets glow strongly. Short term, pseudo shader data is enough. Mid/long term, feed PlayCanvas before/after Engine V2 migration screenshots, Babylon Lite versus Babylon.js golden images, and SuperSplat export before/after images as textures, then route the diff into bloom rims, particle density, and audio bands.

制作に使えそうな技術メモProduction notes

実装上は、移行差分を『スクリーンショット比較だけで終わらせない』のがポイントです。1. 同一 camera pose と DPR cap を固定する。2. legacy path と new path の render target を同じ解像度へ揃える。3. linear/sRGB、tone mapping、post effect、MSDF coverage の差を別 channel に分ける。4. shader で diff heat texture を作り、threshold を越えた場所に inspection lens と rim を出す。5. Grace Cathedral 型の streamed splat では、coarse LOD、chunk arrival、eviction、freeze-fade を state texture にして visual diff と同時表示する。Babylon Lite の発想を借りるなら、CI の数値差分と、鑑賞時の光る差分を同じパイプラインから作るのが強いです。

The key production move is not stopping at screenshot comparison. 1. Lock camera pose and DPR cap. 2. Match render-target resolution between legacy and new paths. 3. Split linear/sRGB, tone mapping, post effects, and MSDF coverage into separate channels. 4. Build a diff-heat texture in shader and show an inspection lens plus rim where thresholds are exceeded. 5. For Grace Cathedral-style streamed splats, expose coarse LOD, chunk arrival, eviction, and freeze-fade as a state texture shown alongside visual diffs. Borrowing the Babylon Lite idea, use one pipeline to produce both CI numeric diffs and glowing runtime diffs.
