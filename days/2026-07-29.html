注目事例と何が面白いかNotable examples and why they matter

注目は PlayCanvas の Gaussian Splat fisheye / relighting / custom shader の三点セット。fisheye は splat と infinite skybox だけを歪ませ、通常 mesh や UI は標準投影のまま残るため、投影の不一致そのものを表現素材にできる。relighting は proxy mesh を別 layer で描き、screen-aligned texture の RGB/alpha を splat fragment に渡す考え方で、これは「後から光を当てる」だけでなく、coverage mask を診断チャンネルとして使える。custom shader は GLSL と WGSL の chunk を並行指定する形なので、WebGL/WebGPU 両対応時の差分を可視化する UI ではなく、画面内 overlay として持つのが良い。Codrops の The Sleepers は、軽い fog、outline、repeating city chunks で視覚強度を出しており、巨大なレンダリング技術よりも、安い shader と配置ルールを重ねる方が短期試作に向くことを再確認できる。

The strongest example cluster is PlayCanvas' Gaussian Splat fisheye, relighting, and custom shader documentation. Fisheye distorts splats and the infinite skybox while leaving regular meshes and UI in normal projection, making the projection mismatch itself usable as visual material. Relighting renders a proxy mesh into a screen-aligned texture and feeds RGB/alpha into splat fragments; that coverage mask can double as a diagnostic channel. Custom shaders require GLSL and WGSL chunks side by side, which argues for an in-scene overlay that shows WebGL/WebGPU drift rather than an external QA table. Codrops' The Sleepers reinforces that lightweight fog, outlines, and repeating chunks can create strong atmosphere faster than heavy rendering systems.

表現・インタラクションのアイデアExpression and interaction ideas

短期で試すなら「投影差を美術化した検査レンズ」が筋が良い。splat/fisheye の境界、tile seam、mip bias、resize pulse をそれぞれ色のチャンネルに割り当て、ポインタ周辺だけ高感度化する。これは前回の interaction memory diff shield の後継で、diff を renderer parity だけに閉じず、projection / shader variant / memory pressure へ広げる案。中長期では、実際の PlayCanvas V2 と WebGPU/WGSL chunk、WebGL/GLSL chunk の render capture を 2枚 texture として読み、差分 heat を空間内に出す。エンタメ寄りには、fisheye を「小惑星」ではなく、ライブ演出の歪む防護膜や、splat の記憶層が伸び縮みする舞台装置として使うとカード UI から離れられる。

The best short-term idea is an inspection lens that aestheticizes projection drift. Assign splat/fisheye boundaries, tile seams, mip bias, and resize pulses to separate color channels, then amplify them near the pointer. This extends yesterday's interaction memory diff shield from renderer parity into projection, shader variant, and memory pressure. Longer term, read actual captures from PlayCanvas V2 WebGPU/WGSL and WebGL/GLSL chunks as two textures and display the heat difference in the scene. For entertainment, use fisheye not as a tiny-planet gimmick but as a warping shield or stage membrane where splat memory layers expand and contract.

制作に使えそうな技術メモProduction notes

PlayCanvas custom splat shader は `app.scene.gsplat.material` に shader chunk を設定し、GLSL と WGSL の両方を更新して `sceneMat.update()` する流れ。fragment stage は splat footprint ごとに走るので、重い noise や texture sampling は overlap が多い scene では危険。vertex stage で分類値を作り、fragment stage へ varying stream として渡す設計が良い。fisheye は初回有効化で shader variant compile が走り、wide FOV では radial sorting が推奨される。Babylon の GS resize leak 修正からは、resize 時の texture 再生成・破棄を明示的に検証対象へ入れるべきだと読める。three.js r185 の HTMLTexture は DOM/情報面を texture 化する方向なので、将来は debug HUD を DOM ではなく shader 内の surface として折り込める。

PlayCanvas custom splat shaders are applied by setting chunks on `app.scene.gsplat.material`, updating both GLSL and WGSL sources, and calling `sceneMat.update()`. Fragment chunks run for every covered splat footprint, so heavy noise or texture sampling is risky in overlap-heavy scenes. A better pattern is classifying once in the vertex stage and passing values through varying streams. Fisheye triggers a shader variant compile the first time it is enabled, and radial sorting is recommended for very wide FOV. Babylon's GS resize leak fix suggests treating resize-triggered texture recreation/disposal as an explicit test target. three.js r185 HTMLTexture keeps pushing DOM/information surfaces toward texture workflows, which can eventually fold debug HUDs into shader surfaces instead of DOM overlays.

The recent trend is Gaussian Splatting becoming a production primitive rather than a viewer feature. The theme worth growing is an overlay where the artwork and validation are not separated: the production effect doubles as QA visualization, and the QA overlay can become entertainment visuals.
