注目事例と何が面白いかNotable examples and why they matter

今日の注目は three.js の TSL test 群と Babylon.js #18820 の offscreen suspension を並べること。前者は shader の数値的な正しさを GPU上で検査する流れ、後者は画面に出ていない viewer を描かないという実行予算の判断。どちらも通常は裏側の品質管理だが、表現として見ると「どの値が信頼できるか」「どの canvas が今生きているか」を可視化できる。Codrops の Run Rob Run のような音反応 goo は形の粘性を見せていたが、次は unit test pass/fail、matrix order、offscreen gate、MSAA sample coverage を音やスクロールで揺らすほうが、単なるエフェクトより深い演出になる。

The notable pairing is three.js TSL tests with Babylon.js #18820 offscreen suspension. The former verifies shader numeric correctness on the GPU; the latter decides not to spend render budget on viewers outside the viewport. Both are normally hidden quality controls, but as expression they can show which values are trustworthy and which canvas is alive. Codrops' Run Rob Run makes audio-reactive goo visible; the next stronger move is to shake unit-test pass/fail, matrix order, offscreen gates, and MSAA sample coverage with audio or scroll.

表現・インタラクションのアイデアExpression and interaction ideas

短期の本命は「TSL Truth Matrix Scope」。TSL test の pass/fail、行列 constructor の row/column 差、select() の scalar branch / component branch 差、tone mapping と procedural helper の期待値差を、full-screen fragment shader の4モードで見せる。ドラッグは expected-value lens、クリック/Space は GPU test pulse。派生案は「Offscreen Layer Budget Scope」。複数の viewer card ではなく、canvas/scene が viewport に入った時だけ発光し、画面外では予算が落ちるようにする。さらに multi-layer height field と MSAA resolve sample を同じ画面に入れ、見えている形・計算したlayer・消費したsampleが食い違う瞬間を演出にする。

The short-term main prototype is TSL Truth Matrix Scope: four full-screen fragment-shader modes for TSL test pass/fail, row/column matrix constructor differences, scalar-branch versus component-branch select behavior, and tone/procedural expected-value differences. Dragging controls an expected-value lens; click or Space triggers a GPU-test pulse. The derived idea is Offscreen Layer Budget Scope: instead of viewer cards, canvases/scenes glow only when they enter the viewport and drop budget when offscreen. Multi-layer height fields and MSAA resolve samples are added so visible shape, computed layer, and consumed sample budget can intentionally diverge.

制作に使えそうな技術メモProduction notes

TSL の今回の流れで重要なのは、shader helper の正しさを「見た目がまあ合う」から「GPU backendごとに数値で合う」へ移すこと。RotateNode の Euler order、mat4(vec4...) の列解釈、plain-number constructor の行解釈、gain() の JS ternary on Node、WGSL の faceForward 名などは、作品上では camera orbit、normal、reflection、audio curve の違和感として出る。PlayCanvas #9167 の multisampled render target sampling は、hardware resolve だけでなく user shader で sampleごとの判断をできる余地を作る。Babylon #18820 は IntersectionObserver 的な viewport gate と render loop を結ぶ設計として、複数の3D埋め込みやギャラリーに効く。MultiTexture は layer追加/削除/差し替えを shader levelで扱えるので、素材差分やステート色の演出に向く。

The key production shift in TSL is moving shader-helper confidence from visually plausible to numerically checked per GPU backend. RotateNode Euler order, mat4(vec4...) column interpretation, plain-number constructor row interpretation, gain() using a JS ternary on a Node, and WGSL faceForward naming can appear in real work as odd camera orbit, normals, reflection, or audio curves. PlayCanvas #9167 opens room for user-shader per-sample decisions rather than only hardware resolves. Babylon #18820 is useful for tying viewport gates to render loops in multi-viewer 3D pages. MultiTexture is promising for shader-level layer add/remove/update, material variation, and state-color expression.
