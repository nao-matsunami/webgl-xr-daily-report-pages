注目事例と何が面白いかNotable examples and why they matter

今日の本命はPlayCanvas v2.23.0のInspector / TextureRenderer / AppStatsのまとまり。WebGPU最適化そのものより、hierarchy、frame graph、render targets、materials、shaders、GPU resourcesを走行中に見る発想が、このプロジェクトの「renderer state theater」に合う。nearest-first streamed GSplat LODは、カメラに近いものから届くという優先順位がそのまま演出になる。Babylon 9.29.0のmin/max reducerとvelocity修正は、値域と前フレームの記憶を同じ画面で扱える点が良い。Codropsのcursor trailは、gridに速度を刻む行為をbrushとして捉え直すことで、診断面を作品の筆跡へ変換できる。

The strongest item today is the PlayCanvas v2.23.0 cluster around Inspector, TextureRenderer, and AppStats. Beyond WebGPU optimization itself, the idea of inspecting hierarchy, frame graph, render targets, materials, shaders, and GPU resources at runtime fits this project's renderer-state theater. Nearest-first streamed GSplat LOD is expressive because priority, meaning what arrives close to the camera first, becomes visible staging. Babylon 9.29.0's min/max reducer and velocity fixes let value range and previous-frame memory coexist. Codrops' cursor trail reframes writing speed into a grid as a brush, turning diagnostics into visible handwriting.

制作に使えそうな技術メモProduction notes

PlayCanvas側で実ログ化するなら `frameId/cameraPosition/splatNodeId/nodeDistance/loadPriority/lodLevel/loadedBytes/splatBudget/resourceBuffers/resourceTextures/resourceRenderTargets/resourcePipelines/bindGroups/gpuMemoryBytes` が良い。TextureRendererの発想を借りるなら、depth / color / velocity / id を小さなpreview tileにして、shader側ではtileごとの明滅や色温度に変換する。Babylon側は `frameGraphBlock/minValue/maxValue/previousWorldMatrixValid/velocityMagnitude/textureRetryCount/cacheHit/mipmapLevel/effectError`。Codrops型のcursor gridは `brushX/brushY/velocity/shapeId/inkDecay` を1枚の低解像度textureとして扱うと、音反応やWebXR controllerにも転用しやすい。

For PlayCanvas logs, useful fields are `frameId/cameraPosition/splatNodeId/nodeDistance/loadPriority/lodLevel/loadedBytes/splatBudget/resourceBuffers/resourceTextures/resourceRenderTargets/resourcePipelines/bindGroups/gpuMemoryBytes`. Borrowing from TextureRenderer, depth/color/velocity/id can become small preview tiles that the shader converts to blinking or color temperature. For Babylon, collect `frameGraphBlock/minValue/maxValue/previousWorldMatrixValid/velocityMagnitude/textureRetryCount/cacheHit/mipmapLevel/effectError`. A Codrops-style cursor grid should store `brushX/brushY/velocity/shapeId/inkDecay` as one low-resolution texture so the same input can be reused for audio and WebXR controllers.

俯瞰メモBird's-eye memo

この数日の流れは、GPUの結果画像よりも、描画途中の所有関係、優先順位、値域、履歴、回復を前景化する方向にまとまってきた。9/29のresidency、9/30のlayer/depth、10/1のviewport/scissor、10/2のbind group / framegraph、10/3のInspector / AppStatsは、全部「見える内部状態」を素材にする同じ流れ。育てる価値が高いテーマは、debug表示をそのまま見せるのではなく、観客の入力や音で内部状態の読み取り方が変わる舞台にすること。

The recent direction is cohering around foregrounding ownership, priority, value ranges, history, and recovery during rendering, rather than only the final GPU image. 9/29 residency, 9/30 layer/depth, 10/1 viewport/scissor, 10/2 bind groups/framegraphs, and 10/3 Inspector/AppStats are all part of the same visible-internal-state theme. The worthwhile long-term direction is not to show debug data directly, but to stage it so viewer input or audio changes how those internal states are read.

サンプルデータの可能性と組み合わせ考察Possibilities for the sample data and combinations

今回の2本は、入力を `cameraX/cameraY/brushX/brushY/pulse/mode`、描画状態を `splatNodeId/nodeDistance/loadPriority/resourceBuffers/resourceTextures/resourceRenderTargets/resourcePipelines/bindGroups/minValue/maxValue/velocityMagnitude/inkDecay/retryCount` として保存できる。音反応ではkickでstream burst、snareでretry spike、低域でsplat budgetを揺らす。WebXRでは左右eyeごとにpriority mapを分け、controller velocityをbrush gridへ書く。MediaPipeでは手の速度をnearest-first queueへ入れ、観客に近い関節から粒子が解像される演出にできる。

These two samples can store inputs as `cameraX/cameraY/brushX/brushY/pulse/mode` and render state as `splatNodeId/nodeDistance/loadPriority/resourceBuffers/resourceTextures/resourceRenderTargets/resourcePipelines/bindGroups/minValue/maxValue/velocityMagnitude/inkDecay/retryCount`. For audio, kick can trigger stream bursts, snare can trigger retry spikes, and bass can modulate the splat budget. For WebXR, split the priority map per eye and write controller velocity into the brush grid. With MediaPipe, hand velocity can feed the nearest-first queue so joints nearer to the viewer resolve into particles first.
