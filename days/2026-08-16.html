今日の重要トピックKey topics today

1. three.js PR #34257 は TSL の RaymarchingBox callback に `stepSize` を渡す変更。volume accumulation、attenuation、transmittance を「何歩進んだか」ではなく「どれだけ距離を積んだか」で制御できる。2. three.js PR #34253 は WebGPURenderer に Weighted Blended OIT の `OITPassNode` を追加した。MRT、attachment 別 blend/clear、shared depth、custom render object functions が揃ったことで、透明物をソート失敗の妥協ではなく合成レイヤーとして扱いやすくなる。3. GaussianSplatMesh では PR #34255 が RGBA8 color を uint32 packed のまま storage buffer に保持する提案、#34254 が per-mesh bounds / frustum culling を追加した。色・境界・sort の扱いが、巨大 splat scene の視覚品質だけでなくメモリ演出の入力にもなる。4. PlayCanvas PR #9167 は WebGPU の multisampled render target を shader で sample 可能にする継続案件。hardware box resolve では出せない sample ごとの発光、輪郭、ノイズ分離が狙える。5. Babylon.js PR #18807 は Sandbox camera preset。大規模 scene を見るための near plane / radius / viewpoint が保存可能になり、camera state を作品内の bookmark / route / rehearsal cue として扱える。

1. three.js PR #34257 passes `stepSize` to the TSL RaymarchingBox callback, so volume accumulation, attenuation, and transmittance can depend on actual marched distance rather than iteration count. 2. three.js PR #34253 adds `OITPassNode`, a Weighted Blended OIT pass for WebGPURenderer. With MRT, per-attachment blend/clear, shared depth, and custom render-object functions in place, transparency becomes a compositing layer rather than a sorting compromise. 3. For GaussianSplatMesh, PR #34255 proposes keeping RGBA8 colors packed as uint32 in storage buffers, while #34254 adds per-mesh bounds and frustum culling. Color, bounds, and sorting now become inputs for both visual quality and memory choreography in large splat scenes. 4. PlayCanvas PR #9167 continues the work of sampling WebGPU multisampled render targets in shaders, opening custom sample glow, contours, and noise separation that a hardware box resolve cannot express. 5. Babylon.js PR #18807 adds Sandbox camera presets. Near plane, radius, and viewpoint settings for large scenes become savable camera state, which can double as bookmarks, routes, and rehearsal cues inside an experience.

制作に使えそうな技術メモProduction notes

RaymarchingBox の callback に `stepSize` が来ると、固定回数ループの見た目を frame rate や scene scale から切り離しやすい。fog density は `density * stepSize`、absorption は `exp(-sigma * stepSize)` のように距離単位で扱える。Weighted Blended OIT は accumulation と revealage の2系統を持つので、作品用には revealage を「見え残り」、accumulation を「光の蓄積」として可視化できる。PlayCanvas #9167 の `bindMultisampled` は WebGPU の multisampled color attachment を後段 shader で `textureLoad(..., sampleIndex)` できるルートで、resolve 前の sample variance を演出データにできる。Babylon #18807 の camera preset は、large scene の near/radius/viewpoint を保存するだけでなく、演出上のカメラキューや比較用 viewpoint set として使える。

Once RaymarchingBox callbacks receive `stepSize`, fixed-iteration looks can be decoupled from frame rate and scene scale. Fog density can use `density * stepSize`, and absorption can use `exp(-sigma * stepSize)` in distance units. Weighted Blended OIT has separate accumulation and revealage channels; for creative work, revealage can be visualized as remaining visibility and accumulation as stored light. PlayCanvas #9167's `bindMultisampled` route lets a later WebGPU shader `textureLoad(..., sampleIndex)` a multisampled color attachment, making pre-resolve sample variance usable as expressive data. Babylon #18807's camera presets are not only saved near/radius/viewpoint settings for large scenes; they are also camera cues and viewpoint sets for comparison.
