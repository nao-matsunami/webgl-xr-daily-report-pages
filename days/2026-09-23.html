今日の重要トピックKey topics today

1. SuperSplat Editor 3.0は、投影、frustum culling、compaction、depth sorting、draw submissionを毎フレームGPU compute側へ寄せ、GPU radix sortとindirect drawingを使う方向に作り替えられている。9/18以降のstream worker / LOD / cleanupの話を、今日は「編集操作そのものがGPU上の作業台になる」方向へ進める。2. three.js 186→187 migration guideでは、PMREM cube render target化、CubeUVReflectionMapping削除、WeakRef / FinalizationRegistry、XR camera matrix、render target bound時のviewport/scissor pixel ratio、pixelationPassのNumber化が並ぶ。9/22のPMREM migration試作を、チェックリスト化と検査レンズへ展開する。3. three.js TSL performance issue #34386は、TSLの遅さをJS node graphよりも巨大WGSL shaderのpipeline compile熱として捉えている。node redundancy、shader size、Metal pipeline compileという軸は、VJや展示で「compileの熱」を見せる演出に使える。4. three.js WGSL/TSL interoperability exampleは、TSL graphと手書きWGSLの橋渡しを実例として持つ。表現面では、node graph、manual shader island、sampler/texture bridgeを1つの画面に置く教材・演出UIの芯になる。5. Babylon.js側はWebGPUとWebGLを併走しつつ、WebGPU-backed WebXRではXRGPUBindingやprojection layerの条件を明示している。9月のPR群ではDoF、KHR_interactivity、dithered material fade、fluid renderer、MultiTextureが継続しており、WebGPU/WebXRのfallbackやfeature parityを日次ウォッチ対象に残す。

The three.js TSL performance issue #34386 frames TSL cost less as JS node-graph time and more as pipeline compile heat from oversized WGSL shaders. The three.js WGSL/TSL interoperability example provides a concrete bridge between TSL graphs and hand-written WGSL. Babylon.js continues WebGPU and WebGL side by side, while WebGPU-backed WebXR requires explicit XRGPUBinding / projection-layer support. September PRs around DoF, KHR_interactivity, dithered material fade, fluid rendering, and MultiTexture keep WebGPU / WebXR fallback and feature parity on the watch list.
