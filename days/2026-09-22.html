今日の重要トピックKey topics today

1. PlayCanvas Engine v2.22.3 が9月21日に公開された。修正は skydome DoF と scene-pass depth、WebGPU resource cleanup と application destroy時のrecovery cancellation、frame preparation前のclustered shadow light reset。9/21のresource lifetime視点を、今日は「アプリ破棄時に残る/消えるGPU状態」へ寄せる。2. PlayCanvas issue #9297 は、SceneDepthReaderやPickerが毎フレームreadbackする場合に WebGPU staging buffer を毎回作成/破棄している問題を扱う。pool化はAPIを変えずに内部寿命だけを整える話で、9/2以降追っているdepth readback / async copyの実ログ化に直結する。3. three.js r186 は引き続き最新リリース。r186には WebGPURenderer、occlusion/timestamp query、shared uniform buffer、DirectRenderPipeline、SunLight CSM、PMREM blur、async dispose などがまとまる。4. three.js 186→187 migrationには、PMREMのcube render target化、CubeUVReflectionMapping削除、WebGPURenderer/WebGLRenderer内部のWeakRef / FinalizationRegistry利用、XR camera行列、render target bound時のviewport/scissor pixel ratio変更、pixelationPassのpixelSizeがNumberになる変更が並ぶ。5. Babylon.js 9.27.1 は normalized occlusion query visibility、Gaussian splats / sprites / particles のframe graph geometry rendering、WebGPU occlusion query begin sequencing、ImageBitmap fast path、streaming compound compaction修正を含む。9/19-9/21のocclusion / frame graph / SOG queueを継続ウォッチする。

1. PlayCanvas Engine v2.22.3 was released on September 21. It fixes skydome depth of field with scene-pass depth, WebGPU resource cleanup and recovery cancellation on application destroy, and clustered shadow light reset before frame preparation. Extending September 21's resource-lifetime view, today's report focuses on GPU state that remains or disappears when an app is destroyed. 2. PlayCanvas issue #9297 discusses pooling WebGPU staging buffers when SceneDepthReader or Picker performs readback every frame. It changes internal lifetime without changing API, directly connecting to the depth readback / async copy log track followed since September 2. 3. three.js r186 remains the latest release and includes broad WebGPURenderer, occlusion / timestamp query, shared uniform buffer, DirectRenderPipeline, SunLight CSM, PMREM blur, and async dispose work. 4. The three.js 186 to 187 migration guide lists PMREM moving to cube render targets, removal of CubeUVReflectionMapping, WeakRef / FinalizationRegistry use in WebGPURenderer / WebGLRenderer internals, XR camera matrix changes, viewport / scissor pixel-ratio behavior changes when render targets are bound, and pixelationPass pixelSize becoming a Number. 5. Babylon.js 9.27.1 includes normalized occlusion-query visibility, frame-graph geometry rendering for Gaussian splats / sprites / particles, WebGPU occlusion query begin sequencing, ImageBitmap fast paths, and streaming compound compaction fixes. This keeps September 19-21's occlusion / frame graph / SOG queue line alive.

注目事例と何が面白いかNotable examples and why they matter

今日いちばん面白いのは、見た目の派手な新機能ではなく、resource cleanup / staging buffer pool / FinalizationRegistry という「片付け」の話が表現素材になりはじめている点。WebGPUやWebGLの資源寿命は普通は隠されるが、destroy、device recovery、readback、shadow resetを状態譜面にすると、展示やVJで「負荷が高いときだけ光る」「破棄待ちの資源が残像になる」「readbackが詰まると粒子が滞留する」という演出にできる。Codrops側では Paper Crumple、Infinite Liquid Glass Grid、MediaPipe face mask、shape-aware ASCII、Datamoshなど、9月の事例が物理・屈折・顔・文字・履歴へ広がっている。これらを今日のcleanup stateと組み合わせると、見た目の効果だけでなく、内部状態の健全性が作品のリズムになる。

The most interesting point today is not a flashy visual feature, but the way cleanup topics such as resource cleanup, staging buffer pools, and FinalizationRegistry can become expressive material. GPU resource lifetime is normally hidden, yet destroy, device recovery, readback, and shadow reset can become a state score: installations or VJ pieces can glow only under load, leave afterimages for resources waiting to be destroyed, or make particles back up when readback stalls. September Codrops examples range across Paper Crumple, Infinite Liquid Glass Grid, MediaPipe face masks, shape-aware ASCII, and Datamosh. Combining them with today's cleanup state makes internal health part of the work's rhythm, not just a debugging concern.

表現・インタラクションのアイデアExpression and interaction ideas

本命案は「Resource Cleanup Staging Pool Scope」。application destroy、WebGPU resource cleanup、recovery cancellation、readback staging buffer pool、clustered shadow resetを1枚のGLSL譜面にする。dragでcleanup pressure、click / Spaceでdestroy pulse。破棄待ちのnode、poolに戻るbuffer、キャンセルされるrecovery、再準備されるshadow lightがそれぞれ違う残像になる。派生案は「TSL PMREM Pixel Migration Scope」。PMREM cube target、TSL/WGSL interop graph、pixelationPassのNumber化をmigration lensでなぞる。dragで移行対象、clickでrebuild pulse。r187移行時の壊れやすい点を、単なるTODOではなく光学的な検査面にする。

The main idea is Resource Cleanup Staging Pool Scope: a GLSL score for application destroy, WebGPU resource cleanup, recovery cancellation, readback staging buffer pools, and clustered shadow reset. Drag controls cleanup pressure; click / Space sends a destroy pulse. Nodes waiting for disposal, buffers returning to the pool, cancelled recovery, and prepared shadow lights each leave distinct afterimages. The derived idea is TSL PMREM Pixel Migration Scope: trace PMREM cube targets, a TSL/WGSL interop graph, and pixelationPass becoming Number-based with a migration lens. Drag selects the migration target; click triggers a rebuild pulse. Fragile r187 migration points become an optical inspection surface rather than a plain TODO list.
